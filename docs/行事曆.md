# 行事曆（pomelo-calendar）

Pomelo 的行事曆：月、週、日、議程四種檢視，行程可以重複、可以設提醒，資料就是標準的 iCalendar（`.ics`）檔，
行事曆視窗沒開著時由背景程式照樣提醒；可選用 CalDAV 與 Nextcloud、Radicale 等伺服器同步。
全部自己寫，不新增任何函式庫相依（解析 iCalendar、重複規則、農曆、時區都在 `pomelo-calendar/` 裡，執行時只有 CalDAV 才需要 `curl`）。

![行事曆：月檢視，含農曆、節氣與多日行程](圖/45-行事曆.png)

## 功能

| 項目 | 說明 |
|---|---|
| 檢視 | 月、週、日、議程（Ctrl+1／2／3／4）；今天、上一個／下一個；點迷你月曆的日期跳過去；每週從週日或週一開始；可顯示週數 |
| 假日與農曆 | 台灣國定假日與補假、補行上班；農曆（初一顯示月份）與二十四節氣；都可以在設定裡關掉 |
| 行程 | 標題、地點、備註、全天、開始／結束、時區、重複、提醒（可多個）、行事曆（分類與顏色）、參與者（文字） |
| 拖曳 | 在月、週、日檢視直接拖曳建立（拖出時段）、拖曳移動、拖下緣調整長度；雙擊編輯 |
| 右鍵選單 | 行程：編輯、複製、建立副本、刪除、更換行事曆顏色；空白處：在此新增行程、新增全天行程、貼上、前往今天；行事曆清單：編輯、更換顏色、只顯示這個、匯出、刪除 |
| 搜尋 | Ctrl+F：搜標題、地點、備註、參與者（過去四個月到未來一年） |
| 鍵盤 | N 新增、T 今天、方向鍵移動日期、PageUp／PageDown 上下個月（週）、Enter 編輯、Delete 刪除、Ctrl+C／V／D 複製、貼上、建立副本、Ctrl+P 匯出本月 PDF、Ctrl+, 設定 |
| 深色模式 | 跟著系統外觀設定 |
| 匯出 | 單一行事曆或全部存成 `.ics`；本月存成 PDF（A4 橫向） |
| 視窗系統 | X11 與原生 Wayland 都能跑（libpomelo 的 `pm_ui_run`） |

## 檔案格式與位置

- 每個行事曆一個檔案：`~/.local/share/pomelo/calendar/<id>.ics`（標準 iCalendar 2.0，`VEVENT`、`RRULE`、`EXDATE`、`RECURRENCE-ID`、`VALARM`、`VTIMEZONE`）。
  名稱存在 `X-WR-CALNAME`，顏色存在 `X-POMELO-COLOR`；讀取時也認得別的程式寫的 `X-WR-CALNAME`、行事曆顏色屬性。
  不認得的行程屬性（`ORGANIZER`、`STATUS`、`X-…`）與別種元件（`VTODO`、`VJOURNAL`）原樣留著、存檔時寫回去。
- **寫檔是原子的**：先寫 `<id>.ics.tmpPID`、`fsync`，再把舊檔以硬連結留成 `<id>.ics.bak`，最後 `rename` 換上去、`fsync` 資料夾。
  當機或斷電時要嘛是新檔要嘛是舊檔，不會出現寫一半的檔案。載入時如果主檔不完整（沒有結尾的 `END:VCALENDAR`），自動改用 `.bak`；
  兩個都壞就把壞檔改名成 `.corrupt-<時間>` 留著、行事曆當成空的，不會被覆蓋。
- 多個程式（視窗、命令列、背景提醒、同步）用 `~/.local/share/pomelo/calendar/.lock` 的檔案鎖協調，寫入前會重讀磁碟上的最新版。
- 刪除行事曆時檔案改名成 `.deleted` 留著，可以自己救回來。
- 設定存在 `~/.config/pomelo/settings.conf` 的 `calendar.*`：`view`、`weekstart`、`weeknum`、`lunar`、`holiday`、`hidden`（隱藏的行事曆 id）、
  `default`（新行程預設的行事曆 id）、`duration`（預設長度，分鐘）、`remind`（預設提醒，分鐘；-1 = 不提醒）、`sidebar`、`sync_minutes`（背景同步間隔，預設 15）。

### 匯入與匯出

- 匯入：檔案管理員雙擊 `.ics`（`text/calendar`）、`pomelo-calendar 檔案.ics`、視窗右上角「⋯ → 匯入 .ics」、或命令列 `--import`。
  同一個 UID（與 RECURRENCE-ID）的行程會被取代，不會重複；幾千筆的檔案不到 0.2 秒（見〈測試〉）。
- 時區：`TZID` 先當 IANA 名稱查系統的時區資料庫；Windows 的名稱（「Taipei Standard Time」「Eastern Standard Time」等常見的）對照到 IANA；
  還是不認得就看檔案裡 `VTIMEZONE` 給的位移，**用最後一個 `STANDARD`／`DAYLIGHT` 的固定位移**（所以這種自訂時區的夏令時間規則不會被解讀）；
  都沒有就當浮動時間。沒有 `TZID` 也沒有 `Z` 的是**浮動時間**：永遠是你所在地的牆上時間。
  寫出時用 IANA 名稱，並依系統時區資料庫自動產生 `VTIMEZONE`（1970～2037 年的轉換點）。
- 重複行程：支援 `FREQ=DAILY|WEEKLY|MONTHLY|YEARLY`、`INTERVAL`、`COUNT`、`UNTIL`、`BYDAY`（含 `2FR`、`-1MO`）、`BYMONTHDAY`（含負數）、`BYMONTH`、`BYSETPOS`、`WKST`、`EXDATE`、`RECURRENCE-ID`。
  重複是在「事件所在時區的牆上時間」展開，所以紐約每天 09:00 的會議跨夏令時間，換成 UTC 會自動差一小時，牆上時間不變。
  **不支援** `BYHOUR`／`BYMINUTE`／`BYSECOND`／`BYYEARDAY`／`BYWEEKNO`／`RDATE`（讀得進來、原樣寫回，但展開時忽略這些）。
  編輯對話窗能表達的規則（每 N 天／週／月／年、指定星期、每月幾號或第幾個星期幾、結束於日期或次數）直接編輯；表單表達不了的規則顯示成「保留原有規則」，不會被改壞。
- 重複行程的「這一次」：改這一次會產生一筆帶 `RECURRENCE-ID` 的修改版；刪這一次是在主行程加 `EXDATE`；「所有行程」改的是主行程。
  拖曳移動重複行程時也會問「只改這一次」還是「改所有行程」（改所有行程時，每週重複的星期會跟著一起位移；其他複雜規則請用編輯視窗改）。

## 假日與農曆

- **國定假日**：2017～2027 年直接用行政院人事行政總處〈中華民國政府行政機關辦公日曆表〉（內建在 `holiday-data.c`，含補假與補行上班）。
  資料來源：政府資料開放平臺 <https://data.gov.tw/dataset/14718>，授權：**政府資料開放授權條款－第1版**
  （Open Government Data License v1.0；可自由重製、散布、改作、商業利用，須標示來源，本文件與 `holiday-data.c` 檔頭都已標示）。
  資料檔用 `pomelo-calendar/tools/gen-holidays.py` 從整理成 JSON 的版本轉出（沒有把第三方整理的 JSON 放進原始碼，只留事實資料）。
  其他年份（2028 年以後）依《紀念日及節日實施條例》**推算**：固定日期的節日、清明（節氣）、春節（除夕到初三）、端午、中秋，
  週六放假前一天補假、週日放假後一天補假；**這只是推算，補班日與臨時調整放假以政府公告為準**（畫面上推算的與公告的在名稱上沒有區別，所以請把 2028 年以後的假日當參考）。
  想看別的地區或自訂假日，可以另外建一個行事曆、匯入想要的 `.ics`。
- **農曆與節氣**：用天文演算法（Meeus《Astronomical Algorithms》第 25、49 章的朔與太陽黃經）依傳統規則推算：以東八區日期為準、冬至所在月為十一月、
  兩個冬至之間有十三個月時第一個沒有中氣的月是閏月。範圍 **1901～2100 年**（超出不顯示）。不是查表，所以沒有表格錯誤的問題。
  測試：1960～2099 年每一天（約 5 萬天）與獨立的查表實作（python `lunardate`）逐日比對、24 節氣與 `ephem`（JPL 等級的天文計算）逐一比對，見〈測試〉。
  已知的小限制：太陽黃經的簡化公式約有 ±6 分鐘的誤差，節氣剛好落在午夜前後幾分鐘時（例如 2040-10-07／08 的寒露）可能與官方曆書差一天；
  朔落在午夜前後 15 分鐘內的少數月份（例如 1978 年 9 月），查表式曆書與天文計算本來就可能不同。

## 提醒

提醒由 `pomelo-calendar --daemon` 負責：**pomelo-session 登入時啟動**（跟 pomelo-notify 一起），行事曆視窗開不開都會通知。

**為什麼用常駐程式而不是 systemd 使用者計時器**：Pomelo 的工作階段是自己的 `pomelo-session`，不保證有 `systemd --user`（Rocky、容器、沒有 logind 的環境），
而且計時器每次觸發都要重新載入全部行事曆、展開重複規則；常駐程式只在檔案變了才重讀、可以睡到下一個提醒，閒置時每 30 秒才醒一次。
單一實例用狀態資料夾裡的 `calendar-daemon.lock`（`flock`），重複啟動不會重複提醒。

- 通知經由 D-Bus 的 `org.freedesktop.Notifications`（pomelo-notify 或任何符合規格的通知服務），按一下通知 → `pomelo-calendar --show UID@開始時刻` 開啟行事曆並選到那個行程。
- **不漏、不重複**：狀態檔 `~/.local/state/pomelo/calendar-alarms.state` 記「上次檢查到哪個時刻」與「已經提醒過的 `UID|這次的開始時刻|提前秒數`」（保留 10 天）。
  每一輪檢查 `(上次檢查, 現在]` 這段時間內到期的提醒，同一個提醒只會出現一次；重啟 daemon、登出再登入也不會重複。
- **睡眠／休眠／關機之後補提醒**：醒來時下一輪檢查會涵蓋整段空白時間（最多往回 7 天）。行程已經結束（且提醒已經過了 5 分鐘以上）的不再提醒；
  還沒結束的補提醒，通知內文會寫「進行中」並註明「（電腦休眠或關機時錯過的提醒）」（遲了兩分鐘以上才註明）。
- 通知服務還沒啟動（剛登入）時，daemon 最多重試 15 分鐘。
- 每個提醒可以是「事件前 N 分鐘／小時／天／週」、「事件開始時」、全天行程的「當天／前一天 09:00」，一個行程可以有多個；匯入的 `VALARM` 相對結束時間（`RELATED=END`）與絕對時間都會正確換算。

## 命令列

```
pomelo-calendar                         開啟行事曆
pomelo-calendar 檔案.ics                匯入 .ics（開啟匯入對話窗）
pomelo-calendar --import 檔案.ics [--calendar 名稱]
pomelo-calendar --export 檔案.ics [--calendar 名稱]
pomelo-calendar --add "標題" --start 時間 [--end 時間 | --duration 分鐘] [--allday]
                [--location 地點] [--notes 備註] [--remind N[m|h|d]]... [--calendar 名稱]
                [--repeat daily|weekly|monthly|yearly] [--every N] [--count N] [--until 日期]
pomelo-calendar --list [--from 時間] [--to 時間] [--calendar 名稱] [--json]
pomelo-calendar --today [--json]
pomelo-calendar --delete UID
pomelo-calendar --show UID[@開始時刻]
pomelo-calendar --sync
pomelo-calendar --caldav-add 名稱 網址 帳號 [--subscribe]    （密碼從標準輸入讀一行）
pomelo-calendar --daemon
pomelo-calendar --help
```

- 時間格式：`2026-11-14 15:00`、`2026-11-14T15:00`、`2026-11-14`（全天）、`15:00`（今天）、`today`、`tomorrow 09:30`、`+2h`、`+30m`、`+3d`。
- `--list` 預設列出從今天 00:00 起七天；`--to` 只給日期時包含那一天；`--from`／`--to` 可以用上面任何一種格式。
- `--list --json` 輸出 JSON 陣列，每筆：`uid`、`title`、`allday`、`start`、`end`（ISO 8601 含時區，全天是日期，`end` 為排他）、`start_epoch`、`end_epoch`、`location`、`notes`、`calendar`、`recurring`、`reminders`（分鐘陣列）。
- `--add` 沒指定 `--calendar` 時放進設定的預設行事曆（沒設就是第一個）；沒指定長度時用設定的預設（60 分鐘）。成功時印出新行程的 `uid`。
- 小幫手「小柚」的快速通道就是呼叫這組指令：「明天下午三點開會」→ `--add`、「我今天有什麼行程」→ `--list --json`（見 [AI小幫手.md](AI小幫手.md)）。

## 與其他部分整合

- **選單列**：點日期時間會彈出迷你月曆（今天的行程、點一天看那天的行程、點行程開啟行事曆）；X11 與原生 Wayland 的選單列都有（`pomelo-calendar --popover 右緣 上緣`）。
- **檔案管理員**：`.ics`（`text/calendar`）預設用行事曆開，雙擊跳出匯入對話窗。啟動器分類是「辦公」。
- **小幫手**：快速通道新增與查詢行程（說法見上）。

## CalDAV 同步（選用）

設定 → CalDAV → 新增帳號（Nextcloud、Radicale、Synology Calendar、Fastmail 等標準 CalDAV；網址、帳號、密碼）。
按「測試連線」會找出帳號底下的行事曆（先用 `current-user-principal` 與 `calendar-home-set`，網址本身是行事曆也可以），選一個就會訂閱並同步。命令列版：

```sh
printf '%s\n' "$密碼" | pomelo-calendar --caldav-add nextcloud https://cloud.example.com/remote.php/dav/ 我的帳號 --subscribe
pomelo-calendar --sync
```

- 讀取與寫回行程：本機的新增、修改、刪除上傳；伺服器端的變動下載。背景程式每 15 分鐘（`calendar.sync_minutes`）同步一次，側欄的「立即同步」可以隨時按。
- **增量同步**：用 CTag 判斷整個行事曆有沒有變、每個資源用 ETag 判斷哪些變了（`calendar-multiget` 一次抓 40 筆）；本機端的變動用「上次同步時行程內容的雜湊」判斷。狀態存在 `<id>.ics.sync`。
- **衝突**：伺服器上的和本機的都改了同一筆 → **以伺服器為準**，本機的修改被蓋掉，並在狀態列與命令列訊息說「N 筆衝突，已以伺服器為準」；上傳時 `If-Match`／`If-None-Match` 失敗（412）也算衝突。
  本機刪掉、伺服器改過：伺服器的版本會回來。伺服器刪掉、本機改過：本機的也刪掉（算一筆衝突）。
- **連線**：用 `curl` 子行程；**TLS 一律驗證憑證，沒有 `-k`**；只接受 `https://`（例外：`http://localhost`、`127.0.0.1` 給本機測試）；不跟隨轉址。
- **密碼存放**：`~/.config/pomelo/calendar/accounts.conf`，權限 0600（一開始就用 0600 建立，沒有被別人讀到的空檔）。
  **沒有用鑰匙圈**（pomelo-keyring 提供的是 Secret Service 的 D-Bus 介面，要處理解鎖與工作階段加密，這一版沒有做）。
  密碼只經由標準輸入交給 curl（`-K -`），**不會出現在命令列、環境變數或日誌**；`--caldav-add` 的密碼也是從標準輸入讀，不是命令列參數。
- 限制：沒有 `sync-token` 增量（RFC 6578），只有 CTag＋ETag；不處理伺服器端的 `VTODO`（原樣忽略）；訂閱的行事曆一個遠端集合對一個本機 `.ics`；
  一個 UID 的所有修改版放在同一個遠端資源裡（標準做法）。

## 測試

放在 `pomelo-calendar/test/`（`make -C pomelo-calendar test BIG=大檔.ics` 跑核心單元測試，不需要 libpomelo 與顯示器）：

- `test-cal.c`：日期與時區（含夏令時間與 Windows 時區名稱、自訂位移）、用 python-icalendar 產生的 `fixtures/icalendar-py.ics`（中文、跳脫、很長的折行、UTC、浮動、全天跨三日、紐約每週一三五＋例外＋修改一次、每月最後一個週五＋提醒、每年生日）、
  Outlook 風格的 `fixtures/outlook-style.ics`（Windows 時區名稱、`RELATED=END` 的提醒、`ATTENDEE`、`DURATION`、`VTODO` 保留）、寫出再讀回再寫要完全相同、折行 ≤ 75 位元組不拆開 UTF-8、
  RRULE 各種情形、儲存（原子寫入、備份、截斷檔還原、兩個都壞）、匯入取代、5000 筆的大檔（解析約 55 ms、匯入兩次約 110 ms）、提醒時間（連續視窗不重複不漏）、日期文字、農曆（春節 2017～2100、閏月、範圍）、節氣、假日。
- `rrule-diff.py`：把隨機產生的上萬條規則（每日／週／月／年、間隔、BYDAY 序號、BYMONTHDAY 負數、BYSETPOS、COUNT、UNTIL，台北、紐約、柏林、雪梨、UTC）同時交給 `cal_expand` 與 python-dateutil，逐次比對，目前 0 筆不同。
- `check-lunar.py`：農曆與節氣與獨立實作比對（見上）。
- `make-demo.py`、`gen-fixtures.py`：產生範例資料與測試檔。
- CalDAV 用本機 Radicale（python `pip install radicale`）端對端測過：訂閱、下載、上傳、伺服器端修改、衝突、雙向刪除、錯誤密碼、自簽憑證被拒絕、命令列看不到密碼。

## 已知限制

- 備註欄只有單行（多行備註會原樣保留，不編輯時不會被改動）；參與者只是文字備註，不會寄邀請信。
- 沒有「待辦事項」（`VTODO` 原樣保留、不顯示）、沒有 `RDATE`、`BYYEARDAY`、`BYWEEKNO`。
- 沒有 CalDAV 的 `sync-token`、沒有鑰匙圈整合、沒有 OAuth（Google 日曆要用應用程式密碼或第三方橋接）。
- 國定假日 2028 年起是推算；農曆節氣有分鐘等級的誤差（見上）。
- 同時開兩個行事曆視窗時各自維護畫面，但都經過檔案鎖寫入並在寫入前重讀，不會互相蓋掉資料。
