# 入侵檢查、日誌檢視器、事件時間線與被攻擊時的處置（主機醫生）

2026-11-14 新增。程式在 `pomelo-doctor/intrusion/`（核心不需要顯示器與 libpomelo；介面是 `gui-intr.h`、`gui-logs.h`、`gui-resp.h`，由補丁併進主機醫生，見 `intrusion/patches/README.md`）。
入口：主機醫生左邊的「入侵檢查」「日誌」「處置」三個分頁、總覽的入侵檢查卡片、`pomelo-doctor --intrusion`／`--logs`／`--evidence`、小幫手的快速通道。

## 誠實原則（所有介面與文件都照這個寫）

這是**在本機上做的檢查**。它只能說「發現跡象」或「沒有發現已知跡象」，**不能說「確定沒有被入侵」**：
高明的入侵（例如核心層的 rootkit）可以欺騙本機上做的任何檢查；套件的雜湊記錄、日誌、基準都存在這台機器上，攻擊者能改。
所以每次結果的最後都有一句：「這是在本機上做的檢查，無法排除高明的入侵…若你懷疑已被入侵，請參考『被攻擊時的處置』，並用外部乾淨的環境（開機光碟）檢查。」
日誌也一樣：日誌乾淨不代表沒被入侵，日誌異常（例如大量失敗登入）也多半只是網路上的自動掃描。

## 一、入侵檢查（`pomelo-doctor --intrusion [--deep] [--light] [--brief] [--json] [--admin] [--only miner] [--days N] [--web] [--no-cache] [--readonly] [--quiet] [--notify]`）

全部唯讀（只寫主機醫生自己的資料夾：基準、「標為正常」、完整性快取、歷史、上次結果）。背景執行時把 CPU 降到 nice 19、I/O 降到 idle class，可取消，有進度。
結論只有三種：**沒有發現已知的入侵跡象**／**發現 N 項可疑跡象（高 X、中 Y、低 Z）**／**發現強烈的入侵跡象，建議立刻處置**（有「嚴重」項目，或高度跡象 3 項以上）。
結束碼：沒有跡象 0、有中低度跡象 1、有高度（含嚴重）跡象 2、錯誤或取消 3。每一項有嚴重度（嚴重／高／中／低／資訊）、可信度、標題、為什麼重要、證據、建議、可能的誤報說明，
可「標為正常」並記住（鍵＝發現的種類｜對象｜內容雜湊前 16 碼，所以檔案內容一變，標記就失效）。資訊等級（例如「更新後需要重新啟動」「自訂單元清單」「對外連線清單」）只是讓你看，不算入結論。

### 偵測原理、能抓與抓不到的

| 類別 | 做什麼 | 抓得到 | 抓不到（誠實） |
|---|---|---|---|
| 系統檔案完整性 | Debian／Ubuntu：讀 `/var/lib/dpkg/info/*.md5sums` 逐檔算 MD5 比對（自己實作，不需要 debsums；排除 dpkg-divert 的檔案）；Fedora／Rocky：`rpm -V`（只比摘要與大小；設定檔改動只是資訊、文件與 ghost 不看）。預設只驗「重點二進位」（`/usr/bin`、`/usr/sbin`、`/bin`、`/sbin`、OpenSSH、libc、PAM、OpenSSL、systemd、/boot 的核心與 initrd），`--deep` 才驗全部執行檔與函式庫。結果快取（修改時間與大小沒變就不重算；`--deep`／`--no-cache` 強制重算）。另列出不屬於任何套件的執行檔 | `ps`、`ls`、`sshd` 這類被換掉的系統程式（關鍵檔案列嚴重）、被換成連結的程式、不見的套件檔案 | 同時改了 md5sums／rpm 資料庫的攻擊；mtime 與大小都偽造且內容換成同大小（快取會漏，deep 才抓得到）；套件之外的路徑（/usr/local、/opt、家目錄） |
| 持久化位置 | cron（/etc/crontab、cron.d、cron.*、使用者 crontab、at）、systemd 單元與定時器（system 與 user：指向 /tmp 或隱藏路徑、名稱偽裝成系統服務卻不屬於套件、新增的、在套件目錄卻不屬於套件）、rc.local、profile.d、shell 啟動檔（curl\|sh、反向 shell、base64 解碼執行…）、`/etc/ld.so.preload`、ld.so.conf.d、`LD_PRELOAD` 環境、PAM（`pam_permit` 加 sufficient、pam_exec、不屬於套件的 `pam_*.so`）、sudoers（NOPASSWD、env_keep LD_PRELOAD）、所有使用者的 authorized_keys（新增、command= 前綴、environment=、權限）、帳號（UID 0 的非 root、系統帳號有登入 shell、密碼欄不是 x、新增的帳號與特權群組成員）、sshd 設定（AuthorizedKeysFile 指到怪位置、AuthorizedKeysCommand、Match 區塊放寬、空密碼）、XDG autostart、modprobe 的 install 規則 | 上述位置裡的可疑內容與「跟第一次基準比多出來的東西」 | 規則表是自行整理的子字串啟發式（`intr-data.c`，資料驅動、不用正規表示式）；改寫過的指令、藏在別處的手法；**基準是第一次檢查時的狀態，當時若已被入侵，基準也包含入侵留下的東西**（介面與 `--rebase` 都這樣說明） |
| 行程異常 | 讀 `/proc`：執行檔已刪除卻在跑（系統目錄且路徑上有新版＝「更新後需要重新啟動」，列資訊，不是入侵）、從 /tmp、/dev/shm、/var/tmp 或家目錄隱藏資料夾執行、`LD_PRELOAD` 環境、記憶體映射載入暫存資料夾的函式庫、名稱與執行檔不符（偽裝成 sshd／systemd、`[kworker]`）、**反向 shell**（shell 的標準輸入輸出接在網際網路 socket 上；unix socket 不算）、孤兒 shell 連外、已知挖礦與殭屍網路名稱與參數（資料驅動表，標明自行整理）、長時間吃滿 CPU 的未知行程、**隱藏行程**（`/proc` 列舉看不到但直接 `stat /proc/<pid>` 查得到；cgroup 有但 /proc 沒有；兩次列舉確認以濾掉短命行程；執行緒不算） | 不夠高明的 rootkit、/tmp 裡的木馬、挖礦程式、反向 shell | 核心層 rootkit 可以讓三個來源一致地說謊；改名躲過名稱比對；只活在別的 PID 命名空間的行程；其他使用者的行程細節需要管理員權限；輕量模式只掃 PID 1～65535 與最近分配的 PID 附近（`--deep` 掃到 pid_max） |
| 網路連線異常 | `/proc/net/tcp*`、`udp*` 對應到行程：對外連線摘要（資訊）、從暫存或隱藏路徑執行的行程連外、礦池常見埠（3333、4444、5555、7777、14444、45700…，標明是啟發式並說明 adb 等誤報）、Tor 埠（9001、9030）、不屬於套件的行程在高埠監聽 | 連到礦池埠的挖礦程式、C2 連線、後門監聽 | 走 443 的挖礦與 C2；不重複實作埠政策（那是網路探索與防火牆的事） |
| 核心與模組 | `/proc/modules` 對照 `modules.dep`（不在目前核心清單的模組）、`/sys/module` 有 `initstate` 但 `/proc/modules` 沒有（被藏起來的模組）、tainted 位元白話解釋（NVIDIA、VirtualBox、DKMS 的外部／未簽章模組是正常的，列資訊）、Secure Boot、lockdown、kptr_restrict、dmesg_restrict（提示）、`--deep` 看 extra／updates 裡不屬於套件的 .ko | 手動 insmod 的模組、不夠高明的隱藏 | 高明的核心 rootkit |
| 檔案系統跡象 | 混淆名稱（「. 」「.. 」「...」、控制字元）、/usr、/etc 下的隱藏資料夾、近期（預設 7 天，可設）被改的重要設定檔（只看 mtime，**不讀 /etc/shadow**）、新增的 setuid（跟基準比；/tmp 與家目錄裡的 setuid 直接列嚴重）、任何人可寫的系統位置、/dev 裡的一般檔案、網頁目錄（/var/www…，`--web` 或 `--deep`）裡的 webshell 特徵字串與 uploads 裡的 PHP | 提權後門、藏東西、放網頁木馬 | webshell 只是特徵字串比對，結果是「可疑」不是「確定」；改過 mtime 的檔案 |

「入口與暴露」（暴力破解、新 SSH 金鑰、對外開放的服務）不重複判斷，直接用安全總覽的結果顯示在入侵檢查頁上，並連到安全總覽。
跟既有檢查重複的發現（行程、/tmp 可執行檔、自動啟動項目、setuid、SSH 金鑰）記在 `dup_of`；併進安全總覽待辦清單時用它去重（`intr_merge_into_sec`）。

### 管理員那一份

`/usr/libexec/pomelo/pomelo-doctor-intr-admin`（經 pkexec；polkit 動作 `tw.fedora.pomelo.doctor-intr-admin`，跟安全總覽的那一份分開）只接受兩種操作，參數逐項驗證（白名單）：
`scan`／`scan-deep`（跑一次入侵檢查，輸出序列化的發現，不含密碼雜湊與檔案內容）、`log 來源 [秒數]`（來源只能是 journal、auth、secure、syslog、messages、kern、dpkg、dnf、ufw、cron、dmesg、wtmp、btmp、audit；秒數 60～一年；只輸出日誌行）。
其他操作、多餘參數、路徑一律拒絕（結束碼 2、什麼都不輸出）。pkexec 會清環境；程式也忽略 `POMELO_DOCTOR_ROOT`（除非測試旗標），並讀呼叫者（PKEXEC_UID）的基準與標記、不寫、也不替他建資料夾。

### 排程與通知

`pomelo-doctor-intrusion.timer`（systemd 使用者定時器，預設啟用，每週一次、隨機延遲 8 小時、不補跑）執行 `--intrusion --light --quiet --notify --scheduled`：
只做不需要管理員、讀取很少磁碟的項目（不驗證完整性、不掃 setuid、不讀 maps）；設定頁可以關掉。高度以上的發現（`ld.so.preload`、系統執行檔被改、隱藏行程、新增 UID 0 帳號、反向 shell…）
用 `pomelo-notify` 通知（`dr_alert_throttle`：24 小時內同一件一次），點通知開入侵檢查頁（`--page intrusion`）。沒有常駐行程。結果與跡象數量記在 `intr-hist.tsv`，入侵檢查頁畫 180 天的走勢。

## 二、日誌檢視器（`pomelo-doctor --logs [--since 時間] [--until 時間] [--level 等級] [--unit 服務] [--grep 字串] [--security] [--source 來源] [--json] [--brief] [--out 檔名] [--anonymize] [--admin]`）

來源：journald（`journalctl -o json`，自己解析 JSON，含位元組陣列訊息與 \u 跳脫）、auth.log、secure、syslog、messages、kern.log、dpkg.log、dnf.rpm.log、ufw.log、cron、dmesg、**wtmp／btmp（自己解析二進位 utmp，不呼叫 last／lastb）**、audit。
utmp 結構在 x86_64、aarch64、i386、armhf 都是 384 位元組（glibc 讓 ut_tv 在所有架構都是兩個 int32），差別只有位元組序：小端與大端自動判斷。
需要權限的來源（例如 `/var/log/auth.log`、btmp、系統 journal）介面上有「以管理員權限讀取」按鈕，走管理員輔助程式，只取日誌行，存在 `$XDG_RUNTIME_DIR`（用完刪除）。
時間格式支援 Ubuntu 22.04 的傳統格式、24.04 的 ISO、journalctl short-iso、Fedora／Rocky 的 secure。

**效能**：進入分頁才讀；串流建立索引（每行 24 位元組，文字留在原檔、journald 正規化成一行存暫存檔並立刻 unlink）；索引上限預設 200 萬行（約 48 MB，超過丟最舊的並標示）；
虛擬捲動只讀看得到的行；閒置不輪詢；「即時追蹤」是使用者開啟、頁面可見時才用 inotify 與 `journalctl -f`（開啟時 tick 縮短到 0.25 秒看一次那兩個檔案描述符，因為 pm_ui 沒有註冊 fd 的介面；關閉就回到 1 秒）。
全文搜尋：多個關鍵字（都要有）、`-排除字`、`"片語"`，不分大小寫，**純子字串比對、不開放正規表示式**（沒有 ReDoS 的問題）。

**journald 很大時的上限（2026-11-14）**：`journalctl --since` 會掃整個 journal（開發主機 3.6 GB 要 5 分鐘以上），所以所有 journalctl 呼叫都帶 `-r -n <行數>`（由新到舊、讀夠就結束；GUI 預設 10 萬行、`--brief` 5 萬行，`--max-lines` 可調），
只看安全事件時在 journalctl 端用 `-t` 依程式名稱先過濾，並用 `--output-fields` 縮小輸出；`--brief`／`--security` 與報告另有總時間上限（預設 10 秒，`--time-limit` 可調），到了就用已讀到的結果並註明「只看了最近的 N 行」。
日誌分頁的索引在背景執行緒建立（畫面立刻可用、有進度、可取消），只讀了最近一部分時狀態列標示，並有「載入較早的日誌」按鈕（每次放大 4 倍，最多 200 萬行）。開發主機實測：`--logs --security --brief --since 7d` 5 分鐘以上 → 9.6 秒。

14 類安全事件自動標示（顏色與圖示，可切換顯示）：失敗登入、成功登入（root、第一次出現的來源 IP 另外標籤）、sudo／su、帳號與群組變更（含 crontab 被改）、密碼變更、SSH 金鑰登入、服務啟停（sshd、cron、防火牆）、
核心錯誤與 OOM、核心模組載入、防火牆擋下（ufw／iptables LOG／任何帶 SRC=、DST= 的核心訊息）、套件安裝與移除、排程執行、sshd 異常、segfault。
點一行展開解析欄位與前後文；右鍵：複製行／本文／來源位址／使用者／服務、以此 IP／使用者／服務過濾、清除過濾、加入時間線、標記為證據、在檔案管理員顯示來源檔、在封包分析器中查看、在網路探索中查看。
匯出（文字或 JSON，含標題說明與時間範圍）可去識別化（遮蔽使用者名稱、主機名稱、IPv4 末段與 IPv6 後段）。

## 三、事件時間線

把「標記為證據」的日誌行與入侵檢查的發現（「加入時間線」）放在同一條時間軸上（自繪，每個事件一個點，顏色依嚴重度，粗框＝證據，白點＝來自入侵檢查；滾輪縮放、拖曳平移）。
「找關聯事件」以選取的事件為中心，前後 10 分鐘內：同一使用者、同一來源 IP、同一行程、同一服務的安全事件，並做間接關聯（錨點只知道使用者時，那個使用者登入的來源 IP 之前的暴力破解也會抓出來），
依關聯分數排序，可單一或全部加入。上面一個「重建：何時開始、做了什麼」的白話敘述。時間線存在 `intr-timeline.tsv`，也會放進證據包。

## 四、被攻擊時的處置（「處置」分頁；入侵檢查頁高度可疑時頂端出現紅色橫幅）

六步驟引導：① 先別關機也別刪檔（關機失去記憶體證據）② 斷開網路（「暫時斷網」用 nmcli 或 rfkill，**一律先問「要…嗎？」**；「恢復網路」；已安裝 pomelo-firewall 時提示它的「封鎖所有出入站（保留本機管理連線）」，不依賴它）
③ 保存證據（「建立證據包」）④ 變更所有密碼與金鑰（列出可能外洩範圍）⑤ 從乾淨環境重新安裝或還原 ⑥ 通報與求助（通用文字，不放特定單位）。這一頁預設只提供唯讀與保存證據；不自動執行任何破壞性動作。

**證據包**（`pomelo-doctor --evidence 資料夾 [--passphrase-file 檔]`；`--verify-evidence 檔`）：`pomelo-evidence-主機-時間.tar.gz`（tar 排序、擁有者歸零），內含 `README.txt`（各檔案用途與時間、驗證方法）、`intrusion.txt`／`.json`、`timeline.txt`／`.json`、
`logs-marked.txt`（標記為證據的行）、`logs-filtered.txt`（目前篩選的日誌，最多 2 萬行）、`processes.txt`（ps）與 `processes-proc.txt`（直接讀 /proc，可跟 ps 對照出隱藏行程）、`connections.txt`（ss）與 `connections-proc.txt`、
`modules.txt`（/proc/modules 與 /sys/module 兩個來源、tainted）、`persistence.txt`（排程、單元、rc.local、profile.d、autostart 的內容）、`file-hashes.txt`（重要檔案的 SHA-256 與屬性；**不收 /etc/shadow**）、`system.txt`。
旁邊一個 `.sha256`（整包的 SHA-256，也顯示在畫面上，可複製）。**不複製密碼雜湊與私鑰**：不讀 shadow、authorized_keys 只留指紋、不複製檔案本體（只有雜湊與屬性）、所有文字寫入前遮蔽 crypt 雜湊、私鑰區塊、`password=`／`token=`／`-pSECRET`／`curl -u 使用者:密碼` 等，
最後再掃一次，有殘留就拒絕建立。可用 gpg 對稱加密（AES256，密碼從標準輸入傳給 gpg，不經命令列；沒有 gpg 就明說；加密成功後只留 .gpg）。介面提醒：請把證據包搬到外部媒體，不要放在受感染的機器上。

## 五、帶去封包分析器與網路探索（契約）

入侵檢查的「網路連線異常」發現（可疑對外連線、反向 shell 特徵、礦池埠、Tor 埠…）、日誌檢視器的來源 IP、事件時間線的事件，都有：

- **「在封包分析器中查看」**（PATH 有 `pomelo-packets` 才顯示）→
  `pomelo-packets --prepare --capture-filter "host <IP>" --display-filter "ip.addr == <IP>" --since <事件時間 ISO8601 UTC> --note "由主機醫生帶入：<行程名稱或發現標題>"`
  （IPv6 的顯示過濾用 `ipv6.addr`）。**契約：`--prepare` 絕不自動開始擷取；使用者在封包分析器的視窗內還要先同意使用須知、自己確認才開始。**
  介面文字寫明：「這會開啟封包分析器，需要你自己確認（同意使用須知）後才開始擷取」。
- **「在網路探索中查看這台設備」**（PATH 有 `pomelo-netscan`，且是區網／本機位址才顯示）→ `pomelo-netscan --show-device <IP>`。

主機醫生這一側（`crosstool.c`）：用 argv 陣列呼叫（`fork`＋`execvp`，不經 shell）、IP 先用 `inet_pton` 驗證（IPv4／IPv6 文字；`1.2.3.4; id`、`$(id)`、換行、`%eth0`、過長一律拒絕）、時間先轉成 `YYYY-MM-DDTHH:MM:SSZ` 並驗證格式、
