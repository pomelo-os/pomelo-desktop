# 容器叢集（pomelo-cluster）設計

> 讓「想玩 Kubernetes 但不會架」的人，用點選的方式建好、用好一個叢集；會架的人也能把別人的叢集或 YAML 匯進來管。
> 選裝套件，裝不裝都不影響桌面其他部分。

## 定位與原則

- **不重寫 Kubernetes。** 叢集引擎用 k3s（Rancher 維護、Apache 2.0、單一執行檔約 70 MB，內建 containerd、flannel 網路、
  Traefik Ingress、local-path 儲存、metrics-server、Helm 控制器），我們做的是上面那一層：部署、管理、儀表板。
- **每一步都是寫死的程式碼。** 體檢、建議、部署指令、檢查規則都在程式裡；小柚只負責聽懂與解釋，不產生指令。
- **跟別的 Pomelo 程式一樣的長相與操作**：libpomelo 原生視窗（pm_ui），13 種語言，右鍵選單，鑰匙圈存密碼。
- **完整相容 Kubernetes**：底下就是標準的 k8s API；kubectl、Helm chart、別人的 YAML 都能直接用，我們不發明自己的格式。

## 三種角色

| 角色 | 是什麼 | 跑什麼 |
|---|---|---|
| 主控台 | 使用者正在用的 Pomelo 桌機 | pomelo-cluster（視窗＋命令列）；需要 kubectl 時用 k3s 執行檔內建的 |
| Server | 控制平面（API、排程、資料庫） | `k3s server`；1 台，或 3 台高可用（內建 etcd） |
| Client | 工作節點，真的跑容器 | `k3s agent`，用 token 加入 |

主控台不必在叢集裡：拿 kubeconfig（憑證）連 server 的 6443 埠。也可以「只用這台電腦」：server＋agent 都裝在桌機上，一台就能玩。

### 服務角色（勾在某一台上，實際上是部署在叢集裡、用節點標籤釘在那台）

| 角色 | 做法 | 使用者看到 |
|---|---|---|
| NFS 儲存 | 那台裝 nfs-kernel-server，匯出 /srv/pomelo-nfs（/etc/exports 只列叢集裡的節點位址，加節點時重寫並 exportfs -ra；不是 *）；叢集裝 nfs-subdir-external-provisioner，成為預設 StorageClass | 「共用儲存：那台的 /srv/pomelo-nfs」 |
| Redis | StatefulSet＋Service，nodeSelector 釘在勾的那台 | 連線位址、密碼 |
| 資料庫 | PostgreSQL／MariaDB／MongoDB 擇一或多個，StatefulSet＋PVC（NFS 或本機） | 連線字串、帳號密碼 |
| 私有映像庫 | registry:2＋PVC；各節點 containerd 設成信任它 | 推送位址 |
| 監控 | k3s 內建 metrics-server（CPU／記憶體）；告警規則在主控台 | 儀表板的圖與警告 |

節點標籤：`pomelo.tw/role.<角色>=true`；taint 不用（使用者不用懂），只用 nodeSelector 把服務釘在指定節點。

## 精靈：四步

1. **要幾台**：「只用這台電腦」（單機學習）或「多台」（填 IP／主機名稱、SSH 帳號密碼或金鑰）。
2. **體檢與建議**：每台 SSH 進去跑固定的 probe 腳本（只讀），卡片顯示硬體摘要、燈號、「建議：server」與理由；
   角色勾選預設照建議，使用者可以改；不合理的組合提醒（不擋），真的不能成立的才擋（零台 server、零台 client）。
3. **確認**：哪台裝什麼、會開哪些埠、資料放哪、要下載什麼。
4. **建立**：逐台逐步顯示進度與日誌，失敗停在那一步、說原因、可以重試；完成給「叢集名片」（API 位址、資料庫連線字串、
   Redis、NFS 路徑、管理帳號；存鑰匙圈，可一鍵複製）。

### 體檢看什麼（probe 腳本，key=value 一行一個）

CPU 核心、記憶體、磁碟（裝置、大小、SSD／硬碟、根目錄剩餘）、網卡速度、是不是虛擬機、作業系統與版本、
時間同步、6443／10250／2379／2380／8472／10250 有沒有被占、已經在跑的東西（Docker、資料庫、k3s）、sudo 能不能用、架構（amd64／arm64）。

### 建議規則（advise.c）

| 狀況 | 建議 | 理由 |
|---|---|---|
| 只有一台 | server＋client | 一台就能玩，之後可加 |
| < 2 核或 < 4 GB | client | 記憶體不夠同時跑控制平面與容器 |
| ≥ 4 核、≥ 8 GB、SSD | server 候選 | 控制平面的資料庫對磁碟延遲敏感 |
| ≥ 3 台合格 | 3 台 server | 任一台壞掉叢集還在 |
| 磁碟最大那台 | NFS | 共用資料放這 |
| 記憶體最多那台 | 資料庫 | 資料庫吃記憶體 |
| 已有 Docker／資料庫在跑 | 只當 client、或不要加入 | 搶埠搶資源 |
| 網卡 100 Mbps | 不建議 NFS | 儲存走網路會慢 |
| 時間沒同步 | 擋，先修 | 憑證會失效 |
| 架構混用（amd64＋arm64） | 允許，提醒映像要有兩種架構 | |

整體模式建議：「單機學習」「小型（1 server＋N client）」「高可用（3 server）」。

## 架構圖（topology.c）

一張圖讓人一眼看懂：主控台在左上，中間一排 Server（控制平面；三台以上畫成 etcd 虛線環），下面一排 Client（工作節點），
每台方塊上掛角色標籤（NFS、DB、Redis、Registry），連上叢集後顯示 Ready／NotReady 燈與 CPU、記憶體用量條。
精靈第 2 步勾角色時即時重畫（規劃中）、第 3 步確認、儀表板與名片都有。cairo 畫成 surface 交給 pm_ui_image。

## 儀表板（建好或匯入之後）

- 總覽：叢集燈號（健康／N 個警告）、節點數與 Ready、Pod 數、CPU／記憶體（metrics-server）、最近事件、警告清單
  （節點 NotReady、Pod 一直重啟、PVC Pending、磁碟壓力、憑證快到期）。
- **總覽（overview.c）**：一頁看完整座叢集——合計幾個應用／Pod／容器在跑、CPU 與記憶體合計；每台機器的 CPU、記憶體使用率；
  「依應用」列出每個 Deployment／StatefulSet／DaemonSet／Job（Pod 數、CPU、記憶體、映像，用記憶體多的排前面），「依機器」列出每台上面跑了哪些 Pod 與用量；
  預設藏 kube-system，可開。Pod 用量是 `kubectl top pods -A`（要有 metrics-server，k3s 內建）；Pod 屬於哪個應用看 ownerReferences（ReplicaSet 去掉雜湊就是 Deployment）。
  新增：型錄部署、自己的映像、套用 YAML。
- **應用詳情**（點總覽裡的應用）：容器（映像、埠、資源要求／上限）、每個 Pod 的即時用量條、看日誌、進容器；選到它的 Service 與網址（selector 是 Pod 標籤的子集合）、
  用到的磁碟區（含 StatefulSet 的 volumeClaimTemplates 展開）、快照清單；動作：重啟、副本數 0／1／2／3、複製、刪除（二次確認）。
- **快照**：沒有靠 CSI 快照（local-path、NFS 都不支援），做法是 ① 把工作負載與選到它的 Service 清成可重建的 JSON，存在
  `~/.local/share/pomelo/cluster/<叢集>/snapshots/<時間>/`（workload.json、meta.txt）；② 每個 PVC 建一個同規格的 `<名>-snap-<時間>`，
  用一個一次性 Job（`rancher/mirrored-library-busybox`，k3s 離線包裡本來就有，`cp -a /src/. /dst/`）把資料整份搬過去。預設先把應用縮到 0 再複製（資料較一致），複製完恢復原副本數；
  複製失敗不會留下半個快照。快照可以「還原」（暫停→清空原 PVC→倒回→恢復）、「複製成新的應用」、刪除（連快照 PVC 一起刪）。
- **複製**（從現況或從快照）：新名字（DNS 規則）；selector 用到的每個標籤值都換掉（含舊名字就取代，沒有就加 `-新名字`），
  所以新舊兩邊的 Service 不會選到對方的 Pod；Service、PVC、StatefulSet 的 serviceName 與 volumeClaimTemplates 的 PVC 都換名；
  可選連資料一起（同一套 Job 複製）或建空的同規格 PVC；對外的 NodePort／LoadBalancer 在新應用改 ClusterIP（不然埠會搶，且 externalTrafficPolicy 等欄位要一起拿掉）；
  ConfigMap／Secret 共用；Ingress 暫不複製。套用失敗會把已建的新工作負載刪掉。
- 節點：每台 CPU／記憶體量表、角色、版本、Pod 數；加節點、移除（先 drain）、升級。
- 工作負載：Deployment／StatefulSet／DaemonSet／Job（副本、就緒、映像）；縮放、重啟、刪除。
- Pod：狀態、重啟次數、節點；日誌（即時）、進入終端機（pomelo-terminal 跑 `kubectl exec -it`）、事件、YAML。
- 服務與 Ingress：類型、埠、網址；點網址開瀏覽器。
- 儲存：StorageClass、PVC。
- 設定：ConfigMap、Secret（值遮罩）。
- 命名空間切換；搜尋。
- **匯入**：
  - 匯入別人的叢集：選 kubeconfig 檔（或貼內容）→ 測連線 → 加入叢集清單，之後跟自己建的一樣管。
  - 套用 YAML：選檔案或貼上 → 顯示會建立／修改哪些資源（dry-run）→ 套用。
  - Helm chart：填 repo／chart／版本，values 轉成表單（用 k3s 內建的 Helm 控制器：建一個 HelmChart 資源，不用 helm 執行檔）。
- 部署應用精靈：填映像、埠、副本數、環境變數、要不要儲存 → 產生 Deployment＋Service＋Ingress，給網址。
- 應用型錄（內建常用的 Helm chart：Nginx、WordPress、Gitea、MinIO、Nextcloud…）。

## 程式結構

```
pomelo-cluster/
  pomelo-cluster.c   視窗、精靈、儀表板、命令列（#include 下面幾個）
  ssh.c              連到節點執行腳本：ssh（密碼用 SSH_ASKPASS，第一次連上就裝我們的金鑰）、本機用 pkexec
  probe.c            體檢腳本（在節點上跑的 sh）與結果解析
  advise.c           建議規則、組合檢查
  deploy.c           部署步驟引擎（背景執行緒，逐步、可重試、日誌）
  kube.c             kubectl 包裝（k3s 內建的 kubectl）、JSON 解析成資料結構、watch
  json.c             跟 pomelo-docker 同一份
```

- 資料：`~/.local/share/pomelo/cluster/clusters.json`（叢集清單、節點、角色）、`<叢集>/kubeconfig`、`id_ed25519`（主控台的金鑰）、
  `known_hosts`（自己一份，不碰使用者的 ~/.ssh）。k3s 執行檔快取在 `~/.cache/pomelo/cluster/`。token、資料庫密碼存鑰匙圈。
- k3s 的安裝不用網路上的 install.sh：執行檔由主控台下載（校驗 sha256）再 scp 到各節點，systemd unit 與
  `/etc/rancher/k3s/config.yaml` 的內容都在程式裡。各節點抓容器映像還是要能連網（或之後支援離線映像包）。
- 測試掛鉤：`POMELO_CLUSTER_SSH=腳本`（代替 ssh；收到 user@host 與 stdin 腳本，回假輸出）、`POMELO_CLUSTER_KUBECTL=腳本`、
  `POMELO_CLUSTER_DATA=資料夾`。真機測試用 QEMU 開幾台 cloud image。

## 套件

- `pomelo-cluster`：Depends openssh-client；Recommends pomelo-terminal、pomelo-keyring；Suggests pomelo-vm（用虛擬機建叢集）。
  不帶 GNOME 相依。k3s 執行檔不進套件。
- 命令列：`pomelo-cluster [--cluster 名稱] nodes|pods|apply 檔案|logs Pod|probe 主機`（給小柚與腳本用）。

## 階段 2 實作備註（services.c）

- 服務角色：Redis（StatefulSet、NodePort 30379）、資料庫（PostgreSQL 30432／MariaDB 30306／MongoDB 30017，帳號 pomelo）、映像庫（registry:2，NodePort 30500；
  每台的 /etc/rancher/k3s/registries.yaml 在裝 k3s 時就寫好）。密碼 gen_password 隨機，只放 Secret；名片用 kubectl 讀回（base64 解碼）。
- 應用型錄是固定範本（不用 Helm）：命名空間 app-<slug>，Deployment／StatefulSet＋PVC＋Service＋Ingress（host 預設 <slug>.<Server IP>.nip.io）。
  WordPress 與 Nextcloud 附自己的 MariaDB（StatefulSet db）。「用我的映像」同一套零件。CLI `pomelo-cluster yaml <app|custom>` 印出 YAML。
- 加節點：dep_join_node 讓 deploy_plan 只排「下載、裝 Client、等 Ready」；token 存在 clusters.json（舊叢集從 server 的 node-token 讀）。
- 移除節點：kubectl drain → delete node → 到那台跑 UNINSTALL_SCRIPT。移除叢集同一支腳本，都在背景執行緒。

## 階段 3 實作備註（ops.c）

- 告警 alerts_from（節點／Pod／PVC／憑證）→ 與 alerts.json 的已通知 key 比對，新的才 notify-send；≥3 個合成一則。背景監看是 systemd --user 的
  pomelo-cluster-watch.timer（每 5 分鐘 `pomelo-cluster watch`，不為「連不上」通知）。
- 升級／更新憑證走部署引擎（dep_upgrade_mode 1／2）。重啟的判斷：記下 MainPID，重啟後看到 PID 換了、active，Server 再看本機節點 Ready 且版本等於新版本，
  Client 從主控台看。**坑**：`restart --no-block` 後服務仍是舊的 active，不看 PID 會提早判成功。
- 備份：`kubectl get … -o json`，backup_clean 刪 status／resourceVersion／uid…，略過 kube-system、objectset.rio.cattle.io 管的、ownerReferences 子物件、
  SA token／helm release secret。NFS 資料用 cpio（NFS 伺服器對使用中的檔案發 delegation，GNU tar 的 O_NONBLOCK 會得到 EAGAIN）。
  還原三段：Namespace＋PVC → 等 nfs 的 PVC 綁定 → 舊資料夾 cp -a 到新 PV 資料夾 → 其餘物件。
- 移除腳本要殺 cgroup（KillMode=process 讓容器程序在停服務後還活著）。

## 階段 4 實作備註（access.c）

- **帳號與權限**：namespace `pomelo-users` 裡一個 ServiceAccount（annotation `pomelo.tw/role`、`pomelo.tw/ns` 記角色與範圍）＋ `kubernetes.io/service-account-token`
  的 Secret（長效 token）＋ 綁定。指定命名空間用 RoleBinding（ClusterRole view／edit／admin），不指定用 ClusterRoleBinding（view／edit／**cluster-admin**）。
  匯出的 kubeconfig 只含該帳號 token；API 位址是 `127.0.0.1` 時換成第一台 Server 的位址；CA 取自各命名空間都有的 ConfigMap `kube-root-ca.crt`。
  刪帳號＝刪綁定、Secret、SA，token 立刻失效（實測 Unauthorized）。**坑**：Buf 的 buf_printf 一次只吐 1 KB，token 加憑證會被截斷成壞掉的 kubeconfig（已改成長度不夠就配大的）。
- **GitOps**：clusters.json 記 git_url／branch／path／auto／commit。同步＝`git clone`（之後 `fetch` ＋ `reset --hard`）→ `kubectl apply`（資料夾有 kustomization 就 `-k`，否則 `-R -f`）。
  有新 commit 才套用；「立即同步」強制套用（把手動改掉的拉回來）；只新增與更新、不刪除（沒有 prune，避免誤刪）。自動同步由 `pomelo-cluster watch` 每 5 分鐘做，失敗只通知一次。
  `GIT_TERMINAL_PROMPT=0`，要密碼就直接失敗；私有倉庫用網址內嵌 token 或 SSH。顯示時網址的 user:token@ 會遮掉。
- **離線包**：`bundle 資料夾` 下載 k3s 執行檔（amd64、arm64）與 airgap 系統映像（.tar.zst）並寫 VERSION；`bundle-import 資料夾` 複製進快取
  （`~/.cache/pomelo/cluster/`，檔名 `k3s-<版本>-<架構>`、`k3s-airgap-<版本>-<架構>.tar.zst`）。建叢集時查不到最新版就改用快取裡最新的版本；
  快取裡有該版本的系統映像就和執行檔一起送到節點 `/var/lib/rancher/k3s/agent/images/`，k3s 啟動時自己匯入（日誌 `Importing images from …`）。
- **多叢集**：首頁每個叢集旁背景（每 30 秒）顯示節點 Ready 數／連不上。
- **備份修正（資料庫還原實測發現）**：舊版把整個 /srv/pomelo-nfs 都打包，舊叢集殘留與 `archived-*` 的資料夾也在裡面，還原時用「最新」去猜會猜到舊資料。
  現在備份只打包「現在還在用的磁碟區」資料夾（外加不是動態儲存建的東西），並把「命名空間／PVC／PV」對應寫進 `nfs-volumes.txt`，還原用它找確切的資料夾
  （沒有這個檔的舊備份才退回猜）。
- 移除腳本先關掉 `Restart=always`（drop-in），不然 `systemctl kill` 之後五秒 k3s 會自己又起來。

## 階段

1. 精靈（單機、多台）、體檢與建議、部署 server／client／NFS、儀表板的總覽／節點／Pod／日誌／終端機、匯入 kubeconfig、套用 YAML。
2. Redis、資料庫、映像庫角色；應用型錄與部署精靈；Helm。
3. 告警與通知中心、備份還原、憑證提醒、升級、小柚（「叢集怎麼了」「哪個 Pod 一直掛」「幫我部署 WordPress」）。
4. 多叢集（首頁燈號）、RBAC 帳號、GitOps、離線映像包。（已完成，見階段 4 實作備註）
