# 防火牆管理員（pomelo-firewall）

**iptables 的好用圖形管理介面。** 就地讀取、就地寫回系統現有的 iptables 規則，用白話顯示、先給風險建議、寫回前備份、預檢、30 秒內沒確認就自動還原。**不取代、不接管** iptables、ufw、firewalld、Docker。

## 1. 定位與做法

| 項目 | 做法 |
|---|---|
| 主模式 | 打開就顯示系統**目前真實**的規則（filter／nat／mangle／raw、IPv4 與 IPv6、含命中計數），白話說明＋可展開看等價的 iptables 指令；新增、編輯、刪除、停用、拖曳重排，都是直接寫回系統 |
| 寫回 | 只重寫「被改動的那幾條鏈」：用一個 `iptables-restore --noflush -c` 交易（`-F 鏈` 後把修改後的規則全部加回去，計數用 `-c` 保留）。沒被改的鏈、表、其他程式的規則一概不碰；沒被編輯的規則**用原文寫回**（不是重新產生，意思不會變） |
| 看不懂的規則 | 解析器是保守的：任何不認得的模組、目標、選項（`-m string`、`-j MASQUERADE`、`-f`…）整條標成「進階規則（唯讀）」，原文完整保留，只能停用、刪除、移動，不能用表單編輯 |
| 別人管理的鏈 | `ufw-*`、`DOCKER*`、`KUBE-*`、`CNI-*`、`cali-*`、`FLANNEL*`、`LIBVIRT_*`、`f2b-*`、firewalld 的 `IN_*`／`FWD_*`… 標示「由某某管理」，預設唯讀（直接改，下次它們重新載入就會被覆蓋）。`DOCKER-USER` 是 Docker 官方建議使用者放規則的地方，可編輯 |
| 自己的鏈 | 只有「攻擊防護」才用 `POMELO_*` 鏈（INPUT 最前面一條跳轉）與 ipset，可一鍵移除乾淨 |
| 持久化 | 不自帶開機還原來取代系統機制：(a) 偵測到 `iptables-persistent`／`netfilter-persistent`（`/etc/iptables/rules.v4`）或 `iptables-services`（`/etc/sysconfig/iptables`）就用它，寫回後「同步存到系統規則檔」（存檔前備份舊檔、保留檔案權限；有 Docker／k3s／ufw 管理的鏈時不存）；(b) 系統沒有任何持久化機制時，才提供選用的 `pomelo-firewall.service`（預設不啟用，同意才 enable） |

## 2. 安全網（不要把自己鎖在門外）

1. **差異預覽**：所有修改先放進「待套用」，按「查看差異並套用」才看到差異（白話，可切換等價指令）。
2. **預檢**：讀 `/proc/net/tcp` 與 `SSH_CONNECTION` 找出目前的遠端連線（SSH、RDP、VNC…），評估修改後這些來源「重新連線」是否被擋；會擋或無法確定就警告，**預設拒絕套用**，除非勾選「我了解」。
3. **自動備份**：每次寫回前 `iptables-save -c` 完整輸出存成帶時間戳的備份（IPv4＋IPv6），保留最近 30 份，可一鍵回復到任何一份。
4. **30 秒倒數**：套用後沒按「保留」就還原到寫回前的備份。還原由 helper 安排：有 systemd 時用 `systemd-run --on-active` 暫時單元，否則用脫離的子行程；**GUI 當掉、連線中斷也會還原**。
5. **競態偵測**：寫回前重新讀取，逐條鏈比對「讀取時的規則雜湊」；編輯期間被別的程式（Docker、ufw、fail2ban…）改動就拒絕，不會蓋掉別人的修改。
6. **緊急還原**：`pomelo-firewall --reset`（只移除 Pomelo 的防護鏈與 ipset）、`--revert`、`--restore 名稱`、`--help`；最後手段 `iptables -P INPUT ACCEPT; iptables -F INPUT`。

## 3. 風險建議（資料驅動，克制）

在**新增／編輯表單、精靈、匯入、基本規則、規則詳情、差異預覽**的下方先給建議，固定格式：一句話標題、為什麼重要、建議做法、按鈕（只改表單內容，不直接套用）、可能的誤報、「不再提示這一條」（記在 `~/.local/share/pomelo/firewall/ignore.txt`）。偵測：

- 高風險埠對所有來源開放（Telnet、FTP、TFTP、rsh、SMB／NetBIOS、RDP、VNC、各資料庫、Redis、Elasticsearch、MQTT、SNMP、Docker API、Memcached）——一張資料表（`advise.c` 的 `risk[]`），改表就能增減；
- SSH 對所有來源開放且沒有限制；入站預設政策為允許且最後沒有擋住的規則；
- 規則永遠不會生效（被前面規則遮蔽）或與前面規則矛盾；
- 規則會切斷目前連線（預檢）、封鎖自己／閘道／DNS／整個區網；
- 允許範圍過大（`/8` 以上）、全部 ICMP（IPv4）、備註與實際埠不符、過期的臨時規則（備註 `exp=YYYY-MM-DD`）；
- 改到別的程式管理的鏈。

只標有明確依據的風險；正常的設定（基本規則、ufw 風格、跳到 ufw 鏈的 INPUT）不提示（單元測試涵蓋）。

## 4. 攻擊防護（核心內執行，不常駐）

| 防護 | iptables 實作 |
|---|---|
| SYN 洪水（每來源 IP） | `-p tcp --syn -m hashlimit --hashlimit-mode srcip --hashlimit-above N/sec --hashlimit-burst B` |
| 並行連線數上限 | `-m connlimit --connlimit-above N --connlimit-mask 32／128` → `REJECT --reject-with tcp-reset` |
| ping 速率 | `-m limit` |
| 無效／畸形封包 | `-m conntrack --ctstate INVALID`；`--tcp-flags` 的 SYN+FIN、全旗標、無旗標、XMAS 等 |
| 反欺騙 | loopback／保留位址從外面進來、`-m addrtype --src-type LOCAL` |
| 自動封鎖 | `hashlimit` 偵測（同一個 IP 在 T 秒內對指定埠超過 N 次新連線）→ `-j SET --add-set pomelo_ban4 src --exist --timeout T`（ipset，到期由核心移除，不需常駐） |
| 重犯加重 | strike ipset 記住 7 天：第 1 次 T、第 2 次 ×6、第 3 次 ×24（上限 30 天） |
| 掃描偵測 | 每來源新連線速率超過上限（沒有 psd 模組，所以是近似，分不出是不是不同埠） |
| 封鎖／白名單 | `pomelo_ban4/6`、`pomelo_allow4/6`（`hash:net`，支援 IPv6 `family inet6`，數萬筆也快）；白名單優先於封鎖；私有網段預設不自動封鎖（`exempt_private`）；你目前連線的來源在開啟防護時自動加入白名單 |

沒有 ipset 時：洪水與連線數限制照常，**手動封鎖退回逐條 iptables 規則**（沒有逾時），自動封鎖需要 ipset（會明說）。核心模組不可用（例如沒有 `xt_hashlimit`）時，整個防護載入失敗、**不留半套規則**，並顯示 iptables 的錯誤訊息。

### DDoS 的誠實說明

本機防火牆只能降低到達本機的洪水對本機的影響、擋掉可以識別的異常來源。**塞滿頻寬的洪水（volumetric DDoS）在到達這台主機之前就已經占滿線路，本機防火牆無能為力**，需要上游處理：聯絡 ISP、雲端或 CDN 的 DDoS 防護、在路由器上限速。這個工具不能「防止 DDoS」。hashlimit 的資料表有大小上限（攻擊者用大量偽造來源可以塞滿它）。

## 5. 與其他防火牆並存

- **ufw**（Ubuntu）、**firewalld**（Fedora／Rocky）在 nftables 之上運作；iptables-nft 的規則與它們**一起評估**，任何一邊丟棄，封包就被丟棄。介面偵測到時會說明，**不會自動停用**任何一個。
- ufw／firewalld 管理的鏈在這裡唯讀；要改它們的規則請用 `ufw allow …`／`firewall-cmd --permanent --add-port=…`（本工具不代為執行）。
- **iptables-nft 與 iptables-legacy 並存**（兩套規則集同時存在）會偵測並警告；介面左下角與設定頁顯示目前用哪一種後端。
- **Docker／k3s／libvirt**：它們的 `FORWARD`／`nat` 鏈標示由誰管理、預設唯讀；不會把它們的規則存進系統規則檔。

## 6. 命令列

```
pomelo-firewall                      開啟視窗（--page overview|rules|protect|lists|log|backup|settings）
pomelo-firewall --status [--json]    狀態
pomelo-firewall --list [--json]      白話說明＋等價的 iptables 指令
pomelo-firewall --allow 埠[/協定] [--from CIDR]     --deny 埠|IP     --remove 鏈:編號 [--table 表] [--ipv6]
pomelo-firewall --basic [basic|desktop|web|strict]  --timeout 秒  --yes  --i-understand
pomelo-firewall --confirm | --revert
pomelo-firewall --protect loose|standard|strict|off  --ban IP [--for 10m|1h|2d|perm]  --unban IP  --bans
pomelo-firewall --backup [原因] | --backups | --restore 名稱
pomelo-firewall --export 檔 | --export-iptables 檔 | --import 檔 | --import-iptables 檔
pomelo-firewall --reset | --disable
```
結束碼：0 成功、1 失敗、2 規則在中途被別人改動、3 預檢發現風險（沒有套用）、4 用法錯誤、5 沒有授權或取消。改變類指令經 pkexec，先顯示差異，預設 30 秒自動還原。

## 7. 檔案與特權

| 路徑 | 說明 |
|---|---|
| `/usr/bin/pomelo-firewall` | GUI 與命令列（不是 root） |
| `/usr/libexec/pomelo/pomelo-firewall-helper` | 特權輔助程式（pkexec；polkit 政策 `tw.fedora.pomelo.firewall-helper`）。只接受固定子命令；規則只能是「該鏈目前原有的原文」或「通過 `fw_parse_rule`＋`fw_rule_spec` 往返驗證的結構化規則」；全部用 argv 陣列執行外部指令（不經 shell）；GUI 只授權一次（`helper serve`） |
| `/var/lib/pomelo-firewall/` | `backups/`（備份）、`history.log`（變更紀錄）、`protect.conf`、`pending`（待確認的還原）、`ban-reasons.tsv` |
| `pomelo-firewall.service` | 選用：開機還原（預設不啟用） |

## 8. 已知限制

- iptables 沒有 nft 的原生集合與逾時：封鎖清單與逾時靠 **ipset**（`ipset` 是建議相依）；規則量大時 iptables 是線性比對（5000 條規則寫回 0.2–0.5 秒，容器內吞吐量約降 1–2 成，見測試報告），封鎖清單請用 ipset。
- 命中的「最近時間」iptables 沒有；只顯示計數與位元組。
- 紀錄頁讀核心日誌（`journalctl -k`）；只在紀錄頁開著時每 5 秒讀一次。容器的網路命名空間預設不輸出 iptables LOG，要在實機上看。
- 自動封鎖不會即時通知（核心裡加入 ipset 沒有事件）；日誌式自動封鎖（fail2ban 類）的核心元件（SSH 失敗登入解析、有上限的滑動視窗計數）已完成並有測試，但尚未做成常駐服務。
- 「停用」的規則存在使用者資料夾（`~/.local/share/pomelo/firewall/disabled.tsv`），不是系統層級。
- 多語系：13 種語言（繁中原文＋zh_CN、en、ja、ko、fr、de、es、it、pt_BR、ru、vi、th、id）；翻譯以機器翻譯＋格式驗證完成，**沒有母語者校對**。泰文在沒有泰文字型的系統上會顯示方塊。
