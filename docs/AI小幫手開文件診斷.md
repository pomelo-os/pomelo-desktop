# 小柚「開文件並寫進去」：診斷、做法、實測（開發記錄，0.42，2026-11-20）

（這份是開發記錄，不裝進小柚的知識庫；給使用者看的摘要在 `AI小幫手.md` 的「開文件並寫進去、查資料寫進文件、想很久怎麼辦」一節，常見問題在 `pomelo-assistant/kb/faq.md`。）

## 診斷、做法、實測

### 起因與診斷（使用者實測）

對小柚說「幫我開啟文件 並將自我介紹寫進去」，畫面一直顯示「思考中」，很久沒結果。診斷（`--chat-test`、自己的 llama-server、假 HOME；使用者正在用的小柚與模型沒動）：

- **不是 Qwen3 的思考模式。** 這台電腦用的是 `Qwen3-VL-4B-Instruct`（設定檔 `assistant.model = qwen3-vl-4b`），2B 也是 Instruct 版，沒有 `<think>`；「思考中」只是介面上「還沒回答」的字樣。
- **真正的原因是三件事疊起來：**
  1. 這句話沒有快速通道，交給模型；模型一輪要先讀新的幾十個 token（約 6 秒）、再用每秒約 4 個 token的速度寫（使用者的 llama-server 記錄也是 246 ms／token）。這台電腦同時還有別的程式在吃 CPU。
  2. 模型一次呼叫一個工具、而且選錯：實測 4B 先 `doc_open "自我介紹.docx"`（找不到）→ `create_file`（只能寫純文字、被使用者的確認視窗擋下）→ 才回一句「你想寫什麼內容？」，一共三輪、約 42 秒，什麼都沒做成；另一句「幫我開一份新文件寫自我介紹」寫到 `max_tokens`（300）上限被截斷，回了殘缺的 `<tool_call>`，用了 75 秒。
  3. 介面沒有進度：本機大腦的「思考中」不顯示等了多久、沒有取消鈕（只有線上大腦有），也沒有逾時，使用者以為卡住了。另外第一次提問、或閒置超過 10 分鐘模型被關掉之後，要先載入模型並讀入約 5500 個 token的系統提示與工具說明，實測約 74 秒（使用者的記錄也是 73.7 秒），這段時間畫面也只是「思考中」。
- 另外幾件事：「開啟文件」是「文件」資料夾（以前就這樣，快速通道），「開新文件」「開一份新文件」「寫一份自我介紹到文件」都沒有快速通道；本機大腦根本沒有「查資料」的工具（只有 `web_search`＝在瀏覽器開 Google，看不到內容），`search_web`、`fetch_url` 只給線上大腦，所以「查今日股價再寫進文件」在本機大腦上做不到（4B 實測回「我無法直接查詢股價」）。

### 修了什麼

**1. 常見的兩步句型走快速通道**（`quick-doc.c` 的 `q_doc_compose`、`quick-compose.c`）：句型由程式聽懂，每一步由程式串，模型只在「真的需要想內容」時才用，而且只寫內容、不呼叫工具（不用寫工具參數，也不會選錯工具）。

| 說法 | 做的事 |
|---|---|
| 「開新文件」「開一份新文件」「開啟新簡報」「開啟新試算表」 | 建空白檔（跳確認視窗）→ 開啟。光說「打開文件」仍是開「文件」資料夾；「打開試算表」「打開簡報」「打開文書處理器」是開那個程式 |
| 「幫我開啟文件 並將自我介紹寫進去」「幫我開一份新文件寫自我介紹」「建立一份自我介紹文件」「寫一份自我介紹到文件」「把我的自我介紹寫進文件並開啟」 | 自我介紹：內容由程式組好（不用模型，立刻完成），跳確認視窗（列出存放位置和將寫入的前幾行），說了「開啟」就接著開 |
| 「開啟文件 並將「你好世界」寫進去」「寫「明天開會」到文件」 | 引號裡的字照寫 |
| 「寫一份關於旅遊的文件」「幫我寫一份請假說明到文件並開啟」「建立一份會議紀錄文件 然後打開它」「寫一份關於旅遊的簡報」 | 請本機模型起草（只寫內容；繁體介面會把模型偶爾寫出的簡體字轉成台灣用字），草稿經確認視窗給你看，同意才建立；簡報依「## 頁標題」「- 重點」拆成頁 |
| 「請查詢今日股價 然後寫到文件內 並開啟文件」 | 見下面「查資料再寫進文件」 |

英文（`quick-lex/en.tsv`：“open a new document”、“open a document and write a self-introduction in it”、“write my self-introduction to a new document”、“search for … and write it into a document and open it” 等）與簡體中文（轉繁體後同一套句型）一樣。

**「自我介紹」是誰的？** 你沒說是誰的時候，預設寫**小柚自己的**（「小柚的自我介紹」：小柚是誰、能做什麼；內容是程式寫死的、跟著介面語言翻譯，不會亂編）；回答裡會說明，並教你怎麼改成自己的。說「我的自我介紹」「幫我寫我的自我介紹到文件」→ 寫成「（你的登入名稱）的自我介紹」，只放名字和幾個空白欄位（關於我、興趣與專長、聯絡方式），**小柚不知道你的背景，不替你編**。這個預設是可以改的（`dq_self_who`，一個函式），要改成「先問你是誰的」也只要改這裡。

**2. 查資料再寫進文件**（本機大腦也能做）：先向搜尋服務（DuckDuckGo，跟線上大腦的 `search_web` 同一個實作）查，畫面上標示「☁ 向搜尋服務查詢：…」；讀前三個結果的網頁、挑數字最多的一頁，連同搜尋摘要一起請模型「只根據這些結果整理、每個數字照抄、沒有的就寫搜尋結果沒有提到」；**程式再查核**：整理出來的內容裡每個 3 位數以上的數字（價格、點數、年份）一定要在來源文字裡找得到，找不到的整行拿掉，回答裡會說拿掉了幾行；最後由程式（不是模型）附上「資料來源」（前三個網址）、「查詢時間」和「由小模型整理、可能有誤」的說明；寫入前一樣經確認視窗。搜尋失敗（網路、搜尋服務拒絕）會明講原因、不建文件；模型整理失敗就把搜尋結果的原文摘要寫進去並說清楚。線上大腦不走這條，它自己會呼叫 `search_web`、`doc_create`。

**3. 「建好之後開啟」不靠模型記得**：模型路徑（沒被快速通道接住的說法）也一樣：這一題呼叫過 `doc_create` 成功、而且使用者的話裡有「開啟／打開」、模型又沒真的開成，就由程式接著 `doc_open`（找不到檔案的 `doc_open` 不算開過）。一次請求裡確認視窗只跳一次（建立那一次），開啟不用再確認；沒按確定就不會開。`doc_open` 找不到檔案時，回給模型的訊息多一句「要新建請用 `doc_create`，不要用 `create_file`」（實測 4B 因此改用 `doc_create`）。

**4. 等待的介面與逾時**（對話視窗與桌面上的小柚泡泡都有）：「小柚正在想…（已等 N 秒）」「正在載入模型…」「小柚正在寫草稿…」「正在上網查資料…」「等你在確認視窗按下「確定」…」；等超過 20 秒多一行「還沒好：這台電腦跑本機模型比較慢。不想等的話可以取消」；本機也有「取消」鈕（泡泡按 Esc）。取消是真的：`http_x` 關掉連線，llama-server 記錄 `srv stop: cancel task`，不會繼續占 CPU（實測）。逾時預設 300 秒（`assistant.local_timeout`，0＝不設上限），超過就說「小幫手想太久了（超過 N 秒），先停下來」並建議把要求說短、換輕量模型或稍後再試。`max_tokens` 300 → 500，寫到一半被截斷的工具呼叫不再顯示成殘缺的 `<tool_call>`，改說「要寫的內容太長，沒寫完就被截斷了」。
- 「工具選擇階段關掉長思考」：這兩個模型本來就是 Instruct 版、沒有思考模式，所以沒有可以關的東西，沒有加 `/no_think` 或 chat template 參數（Qwen3-VL Instruct 不需要）。真正省時間的是少一輪推論：快速通道不用模型、起草只問一次且不帶工具呼叫。起草的請求沿用平常的系統提示與工具說明（只是 `tool_choice: none`），所以 llama-server 的前綴快取不會被洗掉，下一題不必重讀那 5500 個 token。

**5. 確認視窗顯示將寫入的內容**：`doc_create` 的確認視窗以前只寫「開頭：「標題」（共 N 個字）」，現在連內容前幾行（最多 12 行、900 位元組）一起列出。

**6. 知識庫**：「自我介紹」的「介紹」不再被當成「請介紹一下…」這類問功能的問法（不然「幫我開啟文件 並將自我介紹寫進去」會被附上知識庫、而且禁止呼叫工具）；`kb-eval.tsv` 新增 blind6 組。

- 沒有驗證到的：**真的上網查「今日股價」**——早先兩次真搜尋（DuckDuckGo）有回結果：Yahoo 股市的頁面太大（回應超過 400 KB 上限）讀不下來、鉅亨網的頁面內容是程式碼畫的讀不到，搜尋摘要裡沒有當天數字，4B 整理後老實寫「搜尋結果沒有提到」（第一次還重複了 8 行同一句，之後加了去重）；之後連續查詢被 DuckDuckGo 擋下（HTTP 202，連 curl 也一樣），此後 4B、2B 的真搜尋都是「搜尋失敗：服務商拒絕了這個請求（202）→ 沒建文件」，所以上表的 6 次查資料用的是假搜尋服務（`POMELO_ASSISTANT_SEARCH_URL` 指到本機，回傳 3 筆我編的股價摘要，只用來測流程與小模型照抄數字的可靠度）。真實資料的整理品質沒有量到。

- 取消的實測：寫草稿中按「取消」→ 畫面立刻出現「已取消。」，llama-server 記錄 `srv stop: cancel task`、沒有建任何檔。


### 限制（老實說）

- 本機模型寫的草稿品質普通（2B 更不穩），要自己看過；確認視窗會給你看開頭。簡報頁數與段落由模型決定，偶爾會重複同一句（程式會去掉重複行）。
- 查資料再寫進文件：搜尋服務的摘要通常**沒有當天的數字**（實測「今日股價」的真實搜尋結果摘要只有網站介紹；Yahoo 的頁面太大讀不下來、鉅亨網的內容靠程式碼畫出來讀不到），這種情況文件會老實寫「搜尋結果沒有提到」；程式只能保證「寫進去的數字在來源文字裡找得到」，不能保證來源本身正確或是最新的。DuckDuckGo 對連續查詢會回 202 拒絕（實測連續查幾次就被擋），此時小柚明講搜尋失敗、不建文件。
- 沒說「股票代號」的「今日股價」是什麼股票，小柚不猜，原話當搜尋關鍵字。
- 「開啟文件」仍是開「文件」資料夾（沿用以前的習慣）；要新建說「開新文件」。
- 其他語言（日、韓、德、法、西…）沒有這些句型的說法表（只有英文與簡體中文），會交給模型，走原本的路徑。
- 本機模型第一次提問（或閒置超過 10 分鐘後）載入模型並讀入說明約 1～2 分鐘，只是現在畫面看得到在做什麼、可以取消；沒有改這件事本身（縮短系統提示與工具說明是另一件事）。
