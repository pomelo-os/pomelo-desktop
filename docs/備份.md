# 備份（pomelo-backup）

> 設計原則：**備份工具絕不能讓你的資料變得更危險。** 不刪來源、還原不蓋掉現有檔案、只刪自己建立的快照、空間不夠先停止、寫入失敗時上一份備份原封不動。

## 能做什麼

- 在主機醫生裡**檢查電腦有沒有備份**（體檢「開機與系統穩定」多一項、總覽多一張「備份」卡）：偵測 Timeshift、snapper、restic、borg／borgmatic、rsnapshot、Déjà Dup／Duplicity、Back In Time、Bacula／Bareos 用戶端、systemd 定時器與 cron 裡的備份排程、ZFS／LVM 快照、外接硬碟與網路磁碟上的備份庫，以及 Pomelo 自己的備份。雲端同步（Nextcloud、Dropbox…）不算備份，只是同步。
- **沒有備份的話，三步設定**（`pomelo-backup --setup`）：備份什麼 → 備份到哪裡 → 多久一次、保留多久。設定好之後由 systemd 使用者定時器自動執行，不常駐、不耗電。
- **還原**：挑日期、挑檔案（或整個資料夾）；預設不覆蓋現有檔案。檔案管理員右鍵「從備份還原此檔案的舊版本…」。

## 結論一眼看懂

| 燈號 | 意思 |
|---|---|
| 綠 | 最近 N 天（預設 7）內有備份，而且不是放在同一顆硬碟上 |
| 橘 | 已超過 N 天沒更新、最近一次失敗、備份在同一顆硬碟上（硬碟壞掉就一起不見）、或備份幾乎是空的 |
| 紅 | 沒有偵測到任何備份 |
| 灰 | 偵測到備份工具，但無法判斷最近一次是什麼時候 |

**誠實的限制**：「偵測到備份工具的設定」不等於「備份有效」；沒有人替你試著還原過，就不知道備份能不能用。請偶爾還原一個檔案試試看（備份頁的「驗證」也會抽樣比對）。用其他方式備份的人可以按「標為正常（我用其他方式備份）」，90 天後再問。

## 備份格式

預設是 **rsync 硬連結快照**（目的地支援硬連結的檔案系統：ext4、xfs、btrfs、NTFS（ntfs3）…）：

```
<備份位置>/pomelo-backup/<計畫代號>/
  .pomelo-plan                    計畫根目錄標記（沒有它，任何刪除都不會進行）
  2026-11-18_020000/              一份完整快照——用檔案管理員就能瀏覽、複製
    .pomelo-backup                快照標記檔（時間、檔案數、位元組數、狀態、各來源的原路徑）
    Documents/…                   每個來源資料夾一個子資料夾
  2026-11-18_020000.partial/      進行中；成功後才改名成上面那樣（改名是原子的）
  latest -> 2026-11-18_020000
```

沒有變動的檔案與上一份共用硬連結（`rsync -aH --link-dest`），所以十份快照不是十倍大小。FAT／exFAT 不支援硬連結與權限：精靈會偵測並改用**封存模式**（`<日期>.tar.zst`＋`<日期>.meta`，每次完整備份），封存模式可以用 gpg 密碼加密（`.tar.zst.gpg`）。

## 保留策略

每小時／每天／每週／每月各留最新的一份，預設 **7 天、4 週、6 個月**（可調）。「最近 N 個有快照的日子」——備份暫停很久（外接硬碟一個月沒接）也不會因為時間過去就把舊的刪光；最新的一份永遠保留。

**刪除只針對「帶有標記檔」的快照**：刪除前驗證名稱是日期格式、計畫根目錄有 `.pomelo-plan`、快照有 `.pomelo-backup`、路徑（realpath）在計畫根目錄之內；先改名成 `.deleting` 再刪；不跟隨符號連結、不跨檔案系統。快照裡放指向別處的符號連結，也只會解除連結本身。

## 防呆

- 備份位置不能在要備份的資料夾裡面（也不能反過來）。
- 外接碟、網路位置要「目前真的掛著」才備份（沒接上就略過、結束碼 3，不會把資料寫到空的掛載點、塞滿系統磁碟）。
- 先預估這次要寫多少（rsync 乾跑）；空間不夠（預估＋ 5% 或 1 GiB 的餘量）就停止並通知，不留半成品。「空間不足時自動刪最舊的」預設關閉。
- 同一個計畫同時只允許一個備份（flock）；被中斷（關機、拔碟）的 `.partial` 下次執行時清掉，上一份快照完好。
- 權限不足的檔案跳過並計數（警告，不算整體失敗）；備份中消失的檔案（rsync 24）也是警告。
- 電池供電時可略過；預設低優先權（nice 19、ionice idle）。
- 加密的密碼**絕不存放在任何檔案**：每次備份與還原要你輸入，忘記就無法找回；因此加密的計畫只能手動執行。
- 計畫名稱、路徑、排除規則一律驗證（路徑不能含換行或 `..`、排除規則不能以 `+ - ! # ; :` 開頭、計畫代號只能是 `[a-z0-9-]`）；呼叫 rsync／tar／gpg 一律用參數陣列，不經 shell。

## 還原

- 「還原」頁：挑計畫、挑日期（時間軸每個點是一份快照，綠＝成功、橘＝有警告）、瀏覽檔案樹（虛擬捲動，10 萬個檔案的資料夾也快）、勾選要還原的檔案或資料夾。
- 還原到「原位置」或「另一個資料夾」。預覽會顯示檔案數、大小與**幾個同名**；同名的處理方式三選一：**保留現有的（預設）**、**用備份覆蓋**（現有的先搬到 `~/還原前備份/<時間>/`，不是直接蓋掉）、**兩者都保留**（備份版加 `.restored-<時間>` 後綴）。每個檔案先寫暫存檔再改名，寫到一半失敗不會留下壞檔。
- 還原整份快照要再按一次「我了解」。還原寫入紀錄。

## 命令列

```
pomelo-backup [--status] [--list] [--setup] [--run 計畫] [--run-all] [--run-all-due] [--estimate 計畫]
              [--pause 計畫] [--resume 計畫] [--snapshots 計畫] [--ls 計畫 日期 [路徑]]
              [--restore 計畫 日期 路徑… [--to 資料夾] [--overwrite|--both] [--dry-run]]
              [--verify 計畫 [日期] [--full]] [--prune 計畫 [--dry-run]] [--delete-snapshot 計畫 日期 --yes]
              [--new 代號 --name 名稱 --src 資料夾… --dest 位置 …] [--delete-plan 計畫 --yes]
              [--install-timer 計畫] [--ack [天數]] [--unack] [--notify-check] [--detect] [--json] [--help]
```

結束碼：0 成功、1 警告、2 失敗、3 備份位置沒接上、4 另一個備份正在進行。`--status --json` 給主機醫生讀取。

## 排程

每個計畫是 `pomelo-backup@<計畫>.timer`／`.service`（systemd 使用者單元；`OnCalendar` 在 `~/.config/systemd/user/pomelo-backup@<計畫>.timer.d/10-schedule.conf`），`Persistent=true`（關機期間錯過的，開機後補跑）、`RandomizedDelaySec`（避免整點擠在一起）。沒有常駐行程：時間到才由 systemd 叫起來，跑完就結束。沒有 systemd 使用者服務的環境，精靈會給你一行 crontab，並可在登入時執行 `pomelo-backup --run-all-due` 補跑。「外接硬碟插上時」目前是每 30 分鐘偵測一次目的地（沒接上時一下就結束）；沒有 udev 規則。

## 系統設定（選用）

勾選「系統設定」並同意後，由 `pkexec pomelo-backup-admin install-timer` 安裝每天一次的 root 定時器，只讀 `/etc` 與套件清單，匯出到 `/var/lib/pomelo-backup/<uid>/system/`（擁有者是你），再由你的備份計畫當成一般資料夾備份。helper 只接受 `export-now`／`install-timer`／`remove-timer` 與數字的使用者編號，只能替呼叫者自己操作。**預設不啟用。**

## 不包含的東西

- 容器資料請在容器管理員（pomelo-docker）裡備份；虛擬機磁碟很大，預設排除（`*.qcow2`、`*.vdi`、`*.vmdk`、`~/.local/share/containers`），請在虛擬機管理員裡處理。
- SSH 目的地（`user@host:/path`）目前還不支援（輸入驗證與參數注入防護已備妥）；請先把遠端位置用 SMB、NFS 或 sshfs 掛載，再選它。
- gocryptfs／LUKS 目的地只提示（先把備份位置放在已加密的硬碟上即可）。
