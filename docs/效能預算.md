# Pomelo 效能預算

給之後的開發者與測試用。Pomelo 的賣點是輕量與快：新增常駐行程、定時器、輪詢、啟動時的額外工作，都要先對照這份預算。
數字是 2026-11-14 在開發主機（headless pomelo-compositor＋pixman 繪製）量的，主機同時跑著 sonarqube／elasticsearch，
**只適合前後比較，不是絕對值**；CPU 用 user+sys，不用牆鐘時間；記憶體用 PSS（`/proc/PID/smaps_rollup`）。

## 預算

| 項目 | 預算 | 目前 |

寫程式的規則：
1. 要等時間就睡到那個時間（`timerfd(CLOCK_REALTIME, TFD_TIMER_ABSTIME|TFD_TIMER_CANCEL_ON_SET)`＋`poll`），不要固定間隔醒來。
   休眠醒來、時鐘被調整都會叫醒它，所以不必擔心錯過；檔案變動用 inotify。例子：`pomelo-calendar/cli.c` 的 `wait_events()`。
2. 事件迴圈「每個事件都重畫」的程式，要確認重畫本身不會產生新事件。X11 的 `XCopyArea` 預設會回一個 `NoExpose`，
   於是「重畫 → NoExpose → 重畫」無限空轉（0.41 前終端機與截圖工具列就是這樣，每秒 120～250 次、合成器跟著重繪）。
   libpomelo 與終端機、小柚的 GC 已關掉 `graphics_exposures`；自己 `XCreateGC` 的新程式也要關。
3. 開啟時不要同步做「與視窗無關、會花 100 ms 以上」的事（解碼一堆圖、掃整個圖示庫、開外部指令）：先畫出視窗，
   其餘放 `tick` 一次做一點，結果存快取（例：外觀的桌布縮圖 `~/.cache/pomelo/wpthumb/`）。
4. 狀態檔不要每次醒來都 `fsync`；沒有改變就不寫。
5. 沒有使用者動作與設定時，不連網、不開子行程（小柚預設本機、行事曆沒有 CalDAV 就不連線，都已符合）。
6. 新增 session 啟動項目時，放在 `wait_panel_ready()` 之後（桌面出現後才啟動），除非別的東西馬上要用它。

## 量測指令

```sh
# 閒置 CPU 與喚醒（某個行程，10 秒）
P=<pid>; a=$(awk '{print $14+$15}' /proc/$P/stat); v=$(awk '/^voluntary/{print $2}' /proc/$P/status); sleep 10
echo "cpu ticks(1/100s): $(( $(awk '{print $14+$15}' /proc/$P/stat)-a ))  wakeups/s: $(( ($(awk '/^voluntary/{print $2}' /proc/$P/status)-v)/10 ))"

# PSS
awk '/^Pss:/{print $2 " kB"}' /proc/$P/smaps_rollup

# 動態載入成本（重定位）
LD_DEBUG=statistics pomelo-xxx --help 2>&1 | grep -E "relocation|total startup"

# 翻譯 tsv 載入時間（13 種語言各量一次）
for l in en ja th ru de zh_CN; do LANGUAGE=$l POMELO_I18N_DIR=libpomelo/i18n ./trb; done   # trb：呼叫一次 pm_tr 並計時的小程式

# 行事曆載入（5000 筆）與 daemon 系統呼叫
make -C pomelo-calendar test BIG=<big.ics>          # 186 項，印出解析、展開時間
strace -f -c -e trace=fsync,poll,openat pomelo-calendar --daemon   # 閒置時應該幾乎沒有東西
```

量測「開啟到第一個視窗」：在 headless pomelo-compositor 上每 2 ms 跑一次 `wlrctl toplevel list`，
看到新視窗就停（做法見 `~/.tmp/.../scratchpad/perf/appbench.py`；layer-shell 的啟動器與面板沒有 toplevel，改量 CPU 時間）。
閒置掃描：開啟每個程式、等 3 秒、量 4 秒的 CPU ticks 與自願切換次數（`idle.sh`）。**前後都在同一台機器、
同一個負載下各量 5 次以上取中位數。**


## 0.41 第二輪（2026-11-14）新增的規則與基準

**規則**
7. 「一排桌布／圖片預覽」的頁用 libpomelo 的 `pm_thumb_cached()`（只讀快取，很快）＋`pm_thumb_load()`（沒有就解碼並存起來），
   不要在建畫面時同步 `pm_image_load_fit()` 一堆大圖。快取在 `~/.cache/pomelo/wpthumb/`，鍵＝路徑＋修改時間＋大小＋縮圖尺寸；
   寫入先寫暫存檔再 rename（多程式同時寫安全）、檔案長度不對就刪掉重做、目錄不能寫就照舊直接解碼、超過 2000 個檔或 200 MB 清最舊的到剩 75%。
8. 需要跑外部指令更新的畫面（網路、儲存空間）：背景行程做、結果用管線送回來、開啟時先畫上次的快取；能用事件就不要輪詢
   （`nmcli monitor`、核心的 block uevent netlink）。事件來了才掃，其餘才用長間隔（10～30 秒）保底。
9. tick 是固定間隔的計時器：閒置時要拉長。`pm_ui_tick_ms(ms)`（在 tick 裡呼叫，0＝回到預設）讓程式在沒有動畫、背景工作時用 250 ms，
   有事再縮回 66 ms（系統設定：15 → 4 次/秒）。tick 裡不要無條件 `pm_ui_redraw`（儲存空間原本每 0.5 秒重畫一次）。
10. 事件迴圈裡「等到某個時間點」的計時（select／poll 的逾時）要確認那個時間點會被清掉：目標時間已經過了而條件永遠不成立，
    就會每毫秒醒來（看圖程式讀不出來的圖：`hq_due` 永遠不清，閒置 938 次/秒）。用 `strace -c` 看 `pselect6`／`poll` 次數可以抓到。
11. 全螢幕大小的 shm 緩衝（桌布、啟動器 3.6 MB × 3）：`libpomelo` 的 wl.c 現在在視窗 1.5 秒沒有新一幀後，把多的備用緩衝放掉（只留目前這張）；
    常駐程式（面板）另外用 `mallopt(M_MMAP_THRESHOLD, 256 KB)` 關掉 glibc 的動態 mmap 門檻，大塊（整個螢幕的圖）free 後才會還給系統。
12. xkb 鍵盤配置延後到第一次按鍵（或修飾鍵不是空的）才編譯：`xkb_keymap_new_from_buffer` 要 20～30 ms CPU，每個原生程式開第一幀都在白付。
13. `pm_apps()`（所有 .desktop）有快取 `~/.cache/pomelo/apps.bin`（鍵＝語言＋每個 .desktop 的檔名／修改時間／大小加總＋語言包目錄時間）：
    5 ms → 0.3 ms，也省掉翻譯檔載入的記憶體；有檔案新增、刪除、改過、語言換了就整個重掃，快取壞了自動重建。
14. 啟動器／面板開啟時，compositor 回報的第一個 PMW_SIZE 若跟一開始拿到的尺寸一樣就不要重做背景與畫面（原本每次開啟畫兩次、背景算兩次）；
    漸層桌布的背景直接畫成縮小尺寸（約 30 ms → 1 ms）。
15. 滑桿拖曳中不要 `pm_conf_set`（每次寫檔，還會通知所有 X 程式重新載入設定）：拖曳中用本地值預覽，放開才設定
    （keyboard、dock、系統設定的滑桿本來就是這樣；小幫手音量、播放器音量條是這次補的）。

**`pm_conf_set` 的成本（結論：不改，只留警語）**
`pm_conf_set` = 寫檔（原子 rename）＋在 X 根視窗寫 `_POMELO_SETTINGS`，讓還在 X 上的程式（終端機、檔案、計算機、編輯器、pomelo-input…）重新載入設定。
沒有 X 連線的原生程式要臨時 `XOpenDisplay`／`XCloseDisplay`。2026-11-14 在開發主機實測**每次只要 0.2 ms**（40 次平均，含 XInternAtom 往返；上一輪量到的 8.5 ms 是負載高時的數字），
不值得為它改架構。上一輪試過快取連線，XWayland 重啟（`-terminate`，最後一個 X 程式結束就退出）時會 IO error 讓程式結束，所以不要快取 `Display*`。
要注意的是：**XWayland 沒在跑時，這個 `XOpenDisplay` 會把它叫起來**（lazy 啟動，約 100 ms、20 MB），純原生工作階段若 pomelo-input 沒跑，每次設定都會啟動一次 XWayland。
沒有找到不改接收端又零風險的辦法（接收端有 pomelo-input 這種不經過 libpomelo 的 X 程式），所以只在這裡警告：**不要在迴圈、拖曳、動畫、tick 裡呼叫 `pm_conf_set`**。
