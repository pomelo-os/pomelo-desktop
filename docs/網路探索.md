# 網路探索（pomelo-netscan）

給網路管理者在「**自己有權管理的網路**」上做**資產盤點與診斷**的工具：這個網段有哪些設備、開了哪些埠、跑什麼系統、是什麼型號、大概在網路上的哪個位置；有沒有 IP／DHCP 衝突、可疑設備、不該開的埠、異常封包；整個網路的安全狀態如何。全程**唯讀**。

## 邊界（寫死在程式裡，不是設定）

- 只掃描私有網段（10／172.16／192.168／100.64／169.254、IPv6 ULA 與 link-local）。**公網位址完全拒絕，沒有覆寫選項**；每個探測函式在送封包前還會再檢查一次目標是私有位址（防禦縱深）。
- 範圍最大 /22；/22 到 /23 需要確認（「請確認這是你有權限掃描的網路」）；預設只掃 /24。第一次使用要同意使用須知。
- 不做：猜密碼或預設帳密、漏洞利用、拒絕服務、ARP 欺騙／中間人、封包注入、碎片化或誘餌等規避防火牆的掃描。SNMP 只用**你輸入**的團體字串，**不會**嘗試 public／private。
- 只讀設備自己公開的資訊：banner、HTTP 標題與標頭、TLS 憑證主體、UPnP／mDNS／NetBIOS／IPP／SNMP 描述、被動 LLDP／CDP／封包標頭。9100 埠只判斷連得上，**不送列印資料**。
- 節制：三檔速度都有每秒探測上限（溫和 40、標準 150、快速 400）、每台設備並行連線上限；印表機等脆弱設備一次只用 1 條連線並放慢；埠清單預設約 100 個常見埠。
- 結果與歷史只存本機（`~/.local/share/pomelo/netscan/`，原子寫入）。程式不連網，OUI 資料隨系統套件或隨附表。

## 一眼看懂

掃描完成後的第一個畫面是「網路總覽」：頂端狀態橫幅（綠「一切正常」／橘「有 N 件需要注意」／紅「有 N 個問題需要處理」＋一句白話最重要的一件事＋等級）→ 一排數字卡（點了過濾）→ 縮放到剛好的拓樸圖（有問題的節點放大加光暈，正常的淡化）→ 右邊待處理清單（依嚴重度，點一項標出它到閘道的路徑）。

色彩語意全程一致：**綠＝正常、藍＝新出現、橘＝注意、紅＝衝突或問題、灰＝離線／消失、紫＝不明設備**；同時有不同形狀的徽章（圓勾、星、三角、方叉、橫線圓、菱形）和文字，不靠顏色也能分辨。

## 功能與降級

| 探測 | 有進階權限（輔助程式） | 沒有（降級） |
|---|---|---|
| 探索設備 | ARP who-has 探測（精確、會看到同一 IP 的兩個 MAC） | TCP 連線觸發 ARP＋讀 `/proc/net/arp`、`ip -6 neigh`；ICMP 優先用不需要特權的 ICMP 資料報 socket，不行才呼叫 `ping` |
| IP 衝突 | 直接證據（兩個 MAC 回應）＋NetBIOS 網卡位址不一致 | 只有 NetBIOS 不一致的弱證據，**偵測不到完整的 IP 衝突** |
| LLDP／CDP | 被動聆聽（BPF 過濾） | 不可用（SNMP 的 LLDP-MIB 鄰居表仍可用） |
| DHCP 伺服器／rogue DHCP | 送一個 Discover、只聽 Offer（不送 Request） | 不可用 |
| 封包異常 | `--watch` 被動監聽 | 不可用 |
| TTL／TCP 特徵 | 同左 | 同左（TCP 的 MSS、視窗縮放、選項由 `TCP_INFO` 讀取，不需要 raw socket） |
| 其他（埠掃描、服務辨識、mDNS、SSDP、NetBIOS、IPP、SNMP、SMB2） | 同左 | 同左（一般使用者權限即可） |

輔助程式 `pomelo-netscan-helper` 不是 setuid、不執行外部指令、不接受檔案路徑；只有 `arp`／`listen`／`dhcp`／`watch` 四個固定子命令；開好 socket 就**立刻降權並清空 capability**。取得權限有兩種方式：**pkexec（預設，polkit 政策 `tw.fedora.pomelo.netscan-helper`，auth_admin_keep）**，或管理員自己 `setcap cap_net_raw+ep /usr/libexec/pomelo/pomelo-netscan-helper`。預設選 pkexec：和主機醫生的做法一致、不會在檔案系統留下永久的特權檔案、每個工作階段都經過使用者同意。Fedora 45：pkexec 路徑不用額外 SELinux 設定（輔助程式是 `bin_t`，不需要新的域）；setcap 的檔案能力存在 `security.capability` 擴充屬性，rpm 升級後要重新設。

## 位置推斷（誠實說明：網路上的相對位置，不是 GPS）

- **確認的連線（實線）**：SNMP 交換器的 MAC 位址表（每個 MAC 取「該埠上 MAC 最少」的那個埠，也就是最接近設備的埠）、被動 LLDP／CDP（本機直接接的交換器與埠）。
- **推論的連線（虛線）**：沒有二層資訊時，只能畫「設備→閘道」，這**不代表真的接在閘道上**；沒有 L2 資訊但有別處有時，沒歸屬的設備放在「未知上游」。
- 一個交換器埠下學到 3 台以上 MAC，推斷那裡有集線器或 AP（虛擬節點）。純集線器沒有 MAC 與 IP，**掃不到**。
- 設備自述位置：IPP `printer-location`、SNMP `sysLocation`、mDNS TXT `note`、主機名稱含樓層／房間線索。
- 使用者標註（以 MAC 為鍵）：同一交換器埠的設備推論「可能在：…」，可信度 70%（同埠）、同 AP 60%、同交換器 35%，群組超過 12 台或標註比例低會扣分；顯示依據與「這是推論」。
- Wi-Fi：本機有無線網卡時讀 `nmcli` 的掃描快取（不觸發掃描），BSSID 與設備 MAC 比對、粗估「本機到 AP」距離（自由空間＋室內衰減模型，只是參考）。不做追蹤別人的功能。

會畫錯的情況：沒有 SNMP 且沒有 LLDP 時完全沒有二層資訊；MAC 位址表過期（老化時間內的設備移動）；虛擬機與無線客戶端的 MAC 出現在宿主埠；VLAN trunk 埠；多台交換器串接時若只有部分交換器有 SNMP。

## 衝突偵測與解決輔助

| 類型 | 偵測原理 | 誤判可能 |
|---|---|---|
| IP 衝突 | ARP 探測時同一 IP 有兩個以上 MAC 回應（RFC 5227 的探測做法：只問不宣告）；弱證據：NetBIOS 回報的網卡位址與 ARP 不同 | 代理 ARP、VRRP／HSRP 虛擬 MAC 已排除；多網卡設備可能被 NetBIOS 弱證據誤報（標可信度 55%） |
| 同 MAC 多 IP | 鄰居表中同一 MAC 對應多個 IP（排除閘道與虛擬 MAC） | 多 IP 的伺服器、橋接、DHCP 租約更換未過期 |
| 主機名稱衝突 | mDNS／NetBIOS／DHCP／rDNS 同名不同 MAC | mDNS 自動改名（-2）前的短暫狀態 |
| 多台 DHCP／rogue DHCP | 送 DHCP Discover，收集 Offer 的伺服器 IP、配發網段、閘道與 DNS，標出與預期閘道不同者 | 正常的備援 DHCP 也會有兩個 Offer |
| 閘道 MAC 改變 | 與上次掃描記下的閘道 MAC 比 | 換路由器、VRRP 切換 |
| 兩個閘道 | UPnP IGD 描述出現 2 個以上 | 路由器串接本來就是設計 |
| 網段不一致 | DHCP Offer 的網段與本機不同；LLDP 管理位址不在本網段 | — |
| VLAN | LLDP／CDP 的 VLAN 與使用者設定的預期不同（設定 `netscan.vlan`） | trunk／原生 VLAN |
| 靜態 IP 在 DHCP 範圍內 | 需要設定 `netscan.dhcp_range`，且讀得到租約檔時才判斷 | 沒有租約資訊時不判斷 |

每個衝突有嚴重度、涉及設備（名稱、MAC、廠商、型號、OS、位置推論）、「怎麼找到它」（上游交換器與埠、同群組設備、標註位置）、白話原因與建議步驟。輔助工具：`--free-ip`（用 ARP／ping／TCP 確認沒人用，避開已知設備與 DHCP 範圍）、`--plan`（IP 規劃表，可匯出 CSV）、`--why-unreachable IP`（同網段→閘道→ARP→ping→TCP→衝突逐段檢查）、`--history-conflicts`（開始時間、持續多久、是否已解除）。本機側修復只**顯示建議與將執行的 nmcli 指令**；設 `POMELO_NETSCAN_FIX_WRITE=1` 才出現套用按鈕（`POMELO_NETSCAN_DRYRUN=1` 只印指令），套用前會用 ARP／ping 確認新 IP 沒人用。對「別台設備」只給建議，從不自動改動。

## 異常設備

規則表（`conflict.c` 的 `ano[]`：條件→原因→權重），分數 = 100×(1−Π(1−權重))，附前三個原因，**明說是「可疑」不是「確定」**，一鍵「標為正常」會學習。有基準（「把目前網路設為已知基準」或 `--baseline`）時另外比對：新開埠、換交換器埠、MAC 變隨機、類型改變。沒有基準仍用規則並提示「建立基準可以偵測更多異常」。隨機 MAC：手機的隨機 MAC 且沒有開任何服務是正常，不加分；隨機 MAC 卻開了服務、或固定設備突然改用隨機 MAC 才加分。

誤報風險：新設備（訪客手機）在建立基準之前都會是「新出現」；ESP 類 IoT 晶片的 OUI 開 SSH 是不尋常但可能是自製韌體；OS 與 OUI 不一致的規則（Apple OUI 卻是 Ubuntu）可能是雙系統、虛擬機或 OUI 登記資料的歷史因素。

## 埠表與埠政策

- 設備詳情的埠表：埠號／協定、服務、用途（中文白話）、風險、政策判定（允許／不允許／未規範）、banner 等資訊。
- 政策＝範圍＋規則＋例外；範圍：全部、網段、設備類別、標籤（位置）、單一設備（MAC）；規則：允許清單（清單外都不允許）或禁止清單；服務名稱（telnet、smb…）、區間、`tcp:`／`udp:` 前綴；例外要寫理由與到期日。
- **衝突解析規則**：① 範圍越具體越優先（設備 > 標籤 > 類別 > 網段 > 全部）；② 同一具體度「禁止」贏過「允許」；③ 允許清單的意思是「這個範圍內清單以外都不允許」，較具體範圍的允許清單可蓋掉較不具體範圍的禁止；④ 例外只對該規則與該設備有效，到期後規則恢復；⑤ 沒有規則命中＝「未規範」，不算違規。
- 範本（建議，非預設強制）：一般辦公網路、印表機、攝影機／IoT、嚴格、寬鬆；文字格式可匯入／匯出（匯入會驗證：拒絕過大檔案、公網網段、不認得的欄位、超過 128 條規則）；每次修改記在 `policy.log`。
- 政策提到的埠會一併納入探測（單一規則的區間最多展開 64 個，避免政策變成全埠掃描），掃描頁會顯示「因為政策會額外探測 N 個埠」。UDP 只對少數知名服務，**沒有回應不代表關閉**。

## 封包異常（被動）

`pomelo-netscan --watch [秒] [--iface] [--promisc]`：輔助程式用 AF_PACKET 被動收包，**只分析標頭與統計，不儲存封包內容**，記憶體固定上限（約 4 MB 的雜湊表）；沒有流量時阻塞在 `poll`（0 喚醒）；封包率超過上限（預設每秒 20000）時降級為抽樣並標示。規則：ARP 欺騙／中毒（同一 IP 換 MAC，閘道加重）、免費 ARP 洪水、ARP 風暴、水平／垂直掃描、ICMP 掃頻、廣播／多播風暴、SYN／ICMP／UDP 洪水、DHCP 耗盡、畸形封包（SYN＋FIN、NULL、XMAS、長度不符、TTL 0）、雙重 VLAN 標籤、非預期的 STP BPDU 與 IPv6 RA、明文協定（只報埠）、流量暴增（z 分數）、大量對外上傳、大量被拒連線、週期性信標、來源偽造。**觀察範圍限制：在交換式網路上預設只看得到進出本機的流量與廣播／多播；要看整個網段需要鏡像埠（SPAN）或混雜模式搭配。**

## 整體網路安全評估

`--assess [--format text|json|html|pdf]`，結束碼 A／B＝0、C＝1、D 以下＝2。**評分公式**：

1. 每個發現項目的基本扣分：注意 3、警告 8、問題 18、嚴重 30（資訊 0），乘以可信度。
2. 每一類從 100 分起，各項連乘（分數 = 100 × Π(1 − 扣分/100)）；每類中「注意級」合計最多扣 10、「警告級」合計最多扣 25，所以**很多小事壓不過一件大事**。
3. 總分 = 七類加權平均（設備與服務 20、加密與憑證 15、無線 10、設計與分段 15、管理與預設 15、衝突與異常 15、封包行為 10）；沒有資料的類別（沒有無線網卡、沒有監聽）不計入。
4. 上限：有嚴重項目最高 59（F）、有問題項目最高 79、有 3 個以上警告最高 89。等級 A≥90、B≥80、C≥70、D≥60。
5. 被忽略的項目（寫理由、可設到期日）不計分但報告列出；埠政策與安全檢查重複的項目（如 Telnet）只計一次。

檢查項目與是否為進階探測：明文管理頁／Telnet／FTP／POP3／IMAP／SNMP v1v2c（被動，由埠與回應判斷）；TLS 憑證到期、自簽（提示）、RSA < 2048、SHA-1 簽章（被動，一般 TLS 握手）；**TLS 1.0／1.1 是否仍開放（進階探測，`--tls-deep`，多送一個握手，需確認）**；過舊或終止支援的軟體（banner 與內附 EOL 表比對，標「可能過舊」，EOL 表是依各家官方生命週期公告自行整理的事實表，不複製第三方資料）；無線（開放、WEP、WPA1、同 SSID 不同加密＝evil twin 跡象，需要本機有無線網卡）；設計（IoT 與伺服器同網段、消費級分享器、單一 DHCP）；管理（UPnP IGD、疑似預設登入頁，只讀標題，不嘗試登入）。無法判斷的（DHCP snooping／動態 ARP 檢測）明說無法判斷並給出檢查指令。**CVE 比對沒有做**（主機醫生的 SBOM 資料是套件名稱＋版本，和網路服務 banner 沒有 CPE 對應，硬做會大量誤報）。

與主機醫生的關係：主機醫生看**這台電腦**的安全，網路探索看**整個網路**；每次評估會把分數寫到 `~/.local/share/pomelo/netscan/summary.json`（原子寫入），主機醫生補丁可選擇性顯示，但目前沒有修改主機醫生。

## 命令列

見 `pomelo-netscan --help`。SNMP 團體字串請用 `--snmp-file` 或環境變數 `POMELO_NETSCAN_SNMP_COMMUNITY`（命令列參數會被 `ps` 看到）；字串不會寫進任何日誌。

- SNMPv3：`--snmp-v3-file 檔案`（或環境變數 `POMELO_NETSCAN_SNMP_V3_FILE`），檔案內容為 `user=`、`auth=`（md5｜sha｜sha224｜sha256｜sha384｜sha512）、`authpass=`、`priv=`（aes｜aes192｜aes256；不支援 DES）、`privpass=`。**密碼不接受命令列參數**。`--snmp-test <IP>` 只送兩個 GET 驗證帳密；`--snmp-ap-clients <IP>` 讀 AP 的無線用戶端清單（目前只支援 MikroTik）；`--snmp-port N` 改埠（測試用）。
- 拓樸圖：`--topology [--compare] [--at N] [--format png|svg|pdf|json]`；`--compare`＝與上一份掃描比較，`--at N`＝第 N 份歷史快照。
- 給封包分析器等外部程式的入口（會開視窗，參數嚴格驗證，無效就拒絕、結束碼 2）：`--show-device <IP 或 MAC>`（聚焦該設備詳情；掃描歷史找不到就顯示「尚未掃描到這台設備」並提供「現在掃描這台」）、`--show-findings <conflicts|anomalies|packets|policy|assess>`（切到對應的待處理類別）。

## 授權與相依

沒有新增外部相依（不用 nmap、net-snmp、libpcap、openssl 標頭；HTTPS 內容讀取在執行時才 `dlopen` libssl，沒有就只讀憑證）。廠商（OUI）資料：系統的 IEEE 登記表（Debian／Ubuntu `ieee-data` 的 `oui.csv`；Fedora 45、Rocky 9.8 的 `hwdata` 的 `oui.txt`），找不到時用隨附的精簡表 `oui-builtin.h`（`tools/gen-oui.py` 由 IEEE MA-L 公開登記表篩出 149 家常見廠商、約 1 萬筆；IEEE Registration Authority 公開資料）。

## 驗證結果與限制（2026-11-14）

### 封包異常的實驗室驗證（`test/lab/pkt-lab.sh`、`pkt-lab.py`、`pkt-verify.py`）
在**一個**容器裡建立 veth 對（`veth0` 送、輔助程式在 `veth1` 收，同一個網路命名空間，不碰任何真實網卡；`--cap-add NET_ADMIN NET_RAW`，不用 `--privileged`），統計視窗縮成 6 秒，流量都很小而且限時。**21／21 個攻擊情境都偵測到**：ARP 中毒（閘道加重）、ARP 風暴、免費 ARP 洪水、水平掃描（80 台）、垂直掃描（90 埠）、ICMP 掃頻、畸形封包（SYN＋FIN、NULL、XMAS、IP 長度不符）、明文協定、雙層 VLAN 標籤、來源偽造、rogue RA、新的 STP BPDU 來源、DHCP 耗盡（30 個 MAC）、大量被拒連線、SYN／ICMP／UDP 洪水、廣播風暴（約 1500 pps）、多播風暴、流量暴增、週期性信標（每 5 秒）。**正常流量 42 秒（瀏覽、檔案複製、mDNS、DHCP 續租、監控輪詢、BPDU、第一個 RA、一般 ARP）誤報 0 個**；只有一個資訊級的「有人用明文協定」（監控主機用 SNMP v1/v2c 輪詢，是真實提示）。
- 測試中修掉兩個真實問題：①行為剛好跨在統計視窗邊界時會漏報（例如 60 台的掃描被切成 30＋30）→ 現在有兩組錯開半個視窗的統計；②核心把最外層 VLAN 標籤拿掉（網卡卸載）所以認不出雙層標籤 → 輔助程式讀 `PACKET_AUXDATA` 補回；③BPDU 在開始監聽的第一個視窗內的來源視為正常交換器（學習），不再把每個交換器都報成可疑。
- 效能（輔助程式，單一容器、同一台開發機）：約 100 Mbps（1400 位元組的框，9000 pps）15 秒，輔助程式 CPU 約 1.4% 單核、RSS 約 11 MB；6 萬 pps 的小框觸發抽樣降級（介面標「抽樣中」），約 7.8% 單核；沒有流量時阻塞在 `poll`。
- LLDP：Docker 橋接不轉發 LLDP（IEEE 規範），所以在同一個 veth 對上驗證：LLDP 與 CDP 都收到並解出系統名稱、埠、系統描述、管理位址、VLAN、能力。
- 限制：`upload-volume`（大量對外上傳）只有單元層級的設計，沒有在實驗室造 100 MB 的流量；`syn-flood` 等「多個來源」的規則看不出真正的來源是誰。

### 「健康網路」與「有問題網路」（`test/gen-scenario.py`、`test/scenario-test.sh`）
快照格式與掃描器存的一樣（含證據），證據是照實驗室實測收到的樣子手工組出來的。健康網路（TLS 1.2＋、憑證有效、IoT 與伺服器分在不同網段、埠政策零違規、單一 DHCP）得 **A（100）**；有問題網路（Telnet、過期自簽憑證加 TLS 1.0、Windows 7、OpenSSH 5.3、HTTP-only 路由器加 UPnP、IP 衝突含閘道、兩台 DHCP、開放 SSID、同 SSID 不同加密）得 **F（59）**。這組情境還幫忙抓到一個誤報：「IoT 與伺服器同網段」原本只數設備類別，健康網路明明已經分段卻被建議分段 → 改成同一個 /24 內才算。

### 異常設備誤報率
正常網路 142 台（30 台隨機 MAC 手機、10 台新來的訪客手機、6 台經核准的新設備、樹莓派、Windows 桌機、IoT、印表機…）：**調整前誤報 10 台（7.9%）**（新來的訪客手機因為「新出現」被標成可疑）；調整後（隨機 MAC 又沒開服務的新設備只標「新出現」，不算可疑）**誤報 0 台（0%）**，5 台真正不明的新設備（隨機 MAC 開了 SSH／HTTP、Apple OUI 但 Ubuntu 的 SSH、開 Telnet、開 Redis、Cisco OUI 但 Ubuntu）全部抓到（分數 30～65）。資料是自己設計的，樣本不大，結論只代表「沒有明顯的規則問題」，真實網路請先建立基準。

### SNMPv3（`snmp3.c`、`crypto.c`）
- 範圍：USM（RFC 3414）的 noAuthNoPriv、authNoPriv、authPriv。認證：HMAC-MD5-96（**標示不安全**，只為相容舊設備）、HMAC-SHA-1-96、HMAC-SHA-224／256／384／512（RFC 7860，截斷長度 16／24／32／48 位元組）。加密：AES-128／192／256-CFB（RFC 3826；192／256 要求本地化金鑰夠長，MD5 搭 AES-192／256 不支援）。**DES 不支援**（已被淘汰；設定檔寫 `priv=des` 會被拒絕）。流程：引擎探索（可回報的空 GET）→ 密碼轉金鑰（1 MB 展開）與 engineID 本地化 → 帶認證請求；時窗：Report 的 notInTimeWindows 會用 agent 給的 boots／time 自動重新同步一次；其餘 Report（未知使用者、摘要錯、解密錯、等級不符、引擎編號不符）轉成白話原因。只送 GET／GETNEXT／GETBULK，沒有 SET。帳密只來自檔案或環境變數，不猜、不寫日誌；密碼至少 8 字元。
- 密碼學：**自己實作**（MD5、SHA-1、SHA-2、HMAC、AES＋CFB128，約 500 行），不 `dlopen` libcrypto。理由：沒有新相依；不受 OpenSSL 3 legacy provider（MD5、DES）可有可無的影響；每個元件都能用公開的標準測試向量驗證。
- 驗證：①單元測試（`make test`）逐項對照標準測試向量：MD5／SHA-1／SHA-2 全系列（含跨區塊邊界）、HMAC（RFC 2202、RFC 4231）、RFC 3414 附錄 A.3 的密碼轉金鑰與本地化（MD5、SHA-1）、AES-128／192／256（FIPS-197）、AES-CFB128（NIST SP 800-38A F.3.13／15／17）。RFC 3826、RFC 7860 沒有可直接引用的完整訊息向量，SHA-2 的 HMAC 靠 RFC 4231，截斷長度照 RFC 7860 文字。②端對端：`test/snmpv3-test.sh`＋`test/lab/snmpv3-agent.py`（Python 標準函式庫＋ openssl 命令列做 AES，與 C 實作互相獨立）18 項全過：noAuth、MD5、SHA-1+AES-128、SHA-256+AES-128、SHA-384+AES-256、SHA-512+AES-192、密碼錯、加密密碼錯、未知使用者、等級不符、演算法不符、時窗外自動重新同步、無 agent 逾時、命令列拒絕密碼、DES 被拒。③真正的 net-snmp：`test/lab/netsnmp-v3.sh`（容器內 apt 安裝 snmpd，只聽容器的 127.0.0.1）：noAuth、MD5、SHA-1+AES、SHA-256／512+AES-128、SHA-384+AES-256、SHA-512+AES-192 全部成功，錯誤密碼得到「驗證失敗」。

### 已公開 CVE 的保守比對（`cve.c`、`data/cve-banner.tsv`）
- 為什麼不用 libpomelo `sbom.c` 的資料：它是各發行版「套件名稱＋套件版本」的安全公告（debsecan、Ubuntu OVAL、Rocky OSV、Fedora updateinfo），沒有 CPE，對不上網路服務 banner 裡的上游版本字串（例如 `OpenSSH_9.6p1`），硬對會大量誤報。
- 做法：一份**手工整理的小表**（約 40 筆：OpenSSH、Apache httpd、nginx、OpenSSL、PHP、Tomcat、IIS 6.0、vsftpd 後門版、ProFTPD mod_copy、Dropbear、Exim），每筆有受影響範圍「起（含）～修正（不含）」與使用條件；明確的 CPE 風格對照（哪個 banner 欄位、哪個前綴、對應哪個產品）；版本比較支援字母版本（`1.0.1f` < `1.0.1g`、`9.8` < `9.8p1`）。內建一份（編進程式），使用者可在資料夾放 `cve-banner.tsv` 補充。資料來源是各廠商公開公告與 NVD 公開記錄（CVE 編號與受影響範圍是公開事實，摘要為自行撰寫）；隨程式以 GPL-3.0-or-later 提供。**範圍可能有誤差，請對照廠商公告**。
- 呈現：一律標「**可能受影響（依 banner 版本推斷，未驗證）**」，附信心（沒有發行版標記約 50%，條件性的再降）與誤判說明；banner 或系統名稱帶 Ubuntu／Debian／el9 等發行版標記時信心降到約 25% 並說明「修補可能已回移」；全是回移候選的項目嚴重度降為「注意」。納入安全評估、設備詳情與報告（報告可去識別化）；待處理項目可「忽略 30 天」或「不再提示」（鍵含 CVE 集合的雜湊，資料更新出現新的 CVE 時會重新出現）。沒有版本、沒有資料、不認識的產品：不產生任何結果。
- 測試：已知版本、邊界版本（修正版本本身、起始版本、前一版）、回移字串不當作確認、使用者補充資料、優雅降級、整合成待處理項目。

### 與封包分析器（pomelo-packets）的關聯（網路探索這一側）
- 契約：網路探索提供 `--show-device`、`--show-findings`（見「命令列」）；網路探索呼叫 `pomelo-packets --prepare --iface <該設備所在網段的網卡> [--capture-filter …] [--display-filter …] [--since … --until …（ISO8601 UTC）] --note "由網路探索帶入：<名稱>"`。**只有 PATH 找得到 `pomelo-packets` 才顯示入口**。**`--prepare` 絕不自動開始擷取：使用者要在封包分析器視窗內先同意使用須知、自己確認後才開始**；網路探索這一側的按鈕旁寫明「這會開啟封包分析器，需要你自己確認後才開始擷取」。
- 入口：設備詳情與設備右鍵選單（含拓樸圖節點）的「擷取這台的封包…」（`host <IP>`）；封包異常項目的「在封包分析器中查看」（依異常類型：ARP 類 `arp`、DHCP 類 `udp port 67 or udp port 68`、掃描與其他以來源為主的 `host <來源 IP>`、flood 類 `host <目標 IP>`、rogue RA `icmp6`…；時間範圍＝異常時間前 30 秒到後 90 秒）；衝突頁的 IP 衝突項目（`arp or host <IP>`）。
- 安全：呼叫一律用 argv 陣列（`posix_spawnp`），不經 shell；IP、MAC、網卡名稱先驗證格式，過濾條件只允許自己模板產生的字元；名稱類欄位清除控制字元與換行並限制長度（120 位元組、不切斷 UTF-8）。`--show-device`／`--show-findings` 對無效 IP／MAC／類別一律拒絕（結束碼 2）。
- 測試：單元測試（驗證函式、過濾器產生、假的 `pomelo-packets` 放進 PATH 檢查 argv、含換行／引號／分號／反引號／`$()` 的名稱注入、PATH 沒有時不啟動）與 `test/link-test.sh`（參數驗證）；截圖 `test/link-gui.sh`。

- **多國語言**：13 種語言（zh-TW 原文＋ en、de、es、fr、id、it、ja、ko、pt_BR、ru、th、vi、zh_CN）各 1188 句，`python3 i18n/verify.py i18n/<碼>.tsv` 全部缺譯 0、格式不符 0。譯文由模型撰寫並沿用 libpomelo 既有 59 句的譯法保持一致，**沒有經過母語者審稿**。截圖 `shots/lang-<碼>-overview.png`（de、ru、vi、th、fr 另有拓樸、掃描、待處理頁）；德文與俄文檢查後修掉：俄文圖例互相蓋住、應用程式名稱與副標題被截斷、待處理頁摘要與頁籤重疊（改放標題列右側），並縮短過長的短標籤。**泰文在這台開發機顯示成方框**：libpomelo 的字型固定是 Noto Sans CJK TC，沒有泰文字形，是工具箱層級的問題（所有 Pomelo 程式一樣），不是譯文問題。
- 限制：評估與待處理項目裡的「證據」「依據」多是掃描當下組成的中文句子（存在快取裡），沒有做成可翻譯的格式字串；封包異常的標題與建議已改為可翻譯，但事件的細節句（例如「1 秒內對 60 台不同主機送出連線請求」）是監看當下產生的，仍是中文。作業系統名稱與類別理由（規則表的資料）也是中文。

### 先前新增的功能與限制
- 「網路工具」頁：找空 IP、IP 規劃表（可匯出 CSV）、為什麼連不上、衝突歷史。
- 每週排程：`pomelo-netscan-assess.timer`（systemd 使用者定時器，預設關閉；設定頁的開關執行 `systemctl --user enable --now`；溫和速度、不用輔助程式權限、不用 SNMP；C 以下發通知）。
- 主機醫生安全頁顯示「整個網路的安全分數」：補丁 06 讀 `summary.json`（沒有就不顯示）。
- 掃描頁顯示本機無線網卡看到的附近基地台與「粗估」距離（只估本機到基地台）。**開發機沒有無線網卡**，介面用合成的資料截圖驗證。
- 本機側修復（nmcli）只有 dry-run 驗證。
- Fedora 45／Rocky 9.8：`hwdata` 的 `/usr/share/hwdata/oui.txt` 實測可讀；helper 預設走 pkexec（不需要 SELinux 規則，輔助程式是 `bin_t`）；rpm 不放 `%caps`（要的管理員自己 `setcap cap_net_raw+ep`，rpm 升級後要重設）；SELinux 實機行為（pkexec 啟動的輔助程式、setcap 的標籤）在容器裡無法測，**未驗證**；firewalld 偵測沒做。相依展開（`apt -s --install-recommends`、`dnf --assumeno`）在 Ubuntu 24.04、Debian 13、Fedora 45、Rocky 9.8 都沒有帶進 GNOME／GTK 的桌面套件（`libnotify` 會帶 gdk-pixbuf 函式庫，Pomelo 其他套件已是如此）。
