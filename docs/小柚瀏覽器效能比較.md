# 小柚瀏覽器效能比較

> 2026 年 11 月量測。小柚瀏覽器（Pomelo 0.36 開發版）與 Firefox ESR、Chromium 在同一台電腦、同樣的條件下比較
> 啟動時間、記憶體與安裝容量。量測腳本在 `pomelo-browser/bench/`，可以自己重跑。

## 重點

- **記憶體**：三種情況都是最少的。只開一個網頁時約是 Chromium 的一半、Firefox 的 37%；開維基百科少 36%～46%；
  開三個分頁少 21%～36%。網頁開得越多，差距越小（每個分頁的網頁本身要用的記憶體，三個瀏覽器差不多）。
- **啟動**：跟 Chromium 一樣快，視窗約 0.17 秒出現；網頁顯示完成 Chromium 快 0.03 秒。Firefox 慢約 4 倍。
- **容量**：精簡安裝（不裝「建議」的套件）250 MB，三個裡面最小；但 apt 預設會把 WebKitGTK 建議的整套影音外掛一起裝，
  變成 544 MB，反而最大。建議用精簡方式安裝，需要時再加裝 H.264 影片外掛（合計 302 MB，跟 Firefox 差不多）。

三個都是 Debian 13 套件庫裡的版本。

## 測試方法

- **電腦**：Intel Core i5-11400（6 核心 12 執行緒）、46 GB 記憶體。
- **環境**：三個瀏覽器在同一個 Docker 容器（Debian 13）裡輪流跑，畫面是 Xvfb 1280×800，**沒有顯示卡**，
  三個都用 CPU 繪圖；小柚瀏覽器偵測到沒有顯示卡時本來就會改用 CPU 繪圖。容器裡開不了沙箱，三個的沙箱都關掉。
- **設定檔**：每個瀏覽器先啟動一次建立自己的設定檔（不計入），之後的量測都是「第二次以後的啟動」，也就是平常使用的情況。
  Firefox 關掉歡迎頁、預設瀏覽器檢查等第一次啟動才有的畫面；Chromium 加上 `--no-first-run`。
- **啟動時間**：從執行指令開始計時，記錄「視窗出現」與「網頁顯示完成」（視窗標題變成測試網頁的標題）的時間。
  測試網頁是本機的小檔案，不受網路影響。
- **記憶體**：網頁載入後等 5～20 秒，把這個瀏覽器所有行程的 **PSS** 加起來。PSS 會把共用的函式庫按比例分攤，
  不會像 RSS 一樣重複計算，最接近「這個瀏覽器實際佔用多少記憶體」。分三種情況：
  - 空白網頁：上面那個本機小網頁。
  - 維基百科：中文維基百科「臺灣」條目（圖片多、內容長）。
  - 三個分頁：中文維基「臺灣」、英文維基「Taiwan」、example.com。
- **次數**：每一項量 3 次，取中位數。

|---|---:|---:|---:|
| 精簡：套件／下載／磁碟 | 58／67 MB／250 MB | 7／125 MB／385 MB | 2／80 MB／295 MB |
| 預設：套件／下載／磁碟 | 194／167 MB／544 MB | 68／143 MB／473 MB | 2／80 MB／295 MB |
| 精簡＋H.264 影片外掛 | 94／85 MB／302 MB | － | － |

- 小柚瀏覽器本身只有約 130 KB，容量幾乎都是 WebKitGTK（引擎本身約 120 MB）、GTK4 與 GStreamer（播放影音）。
- **預設安裝為什麼反而最大**：WebKitGTK「建議」安裝完整的影音外掛（gstreamer1.0-plugins-bad、gstreamer1.0-libav，
  連帶 FFmpeg、各種編解碼器與機器學習函式庫）、圖片工具（ImageMagick、Ghostscript）與 xdg-desktop-portal-gtk，
  apt 預設會一起裝。這些大多用不到。
- **建議的裝法**：用精簡方式安裝（Pomelo 安裝說明裡的「想裝到最精簡」）。精簡安裝已經有 GStreamer 的 base 與 good 外掛
  （WebM、VP8／VP9、Opus 等格式）；網站影片是 H.264／AAC 格式而播不出來時，再加裝 `gstreamer1.0-libav`（合計 302 MB）。
- Firefox 把大部分函式庫包在自己的套件裡，所以只有 2 個套件；Chromium 有一部分用系統的函式庫。

## 為什麼比較省

- **只有外殼是自己寫的**：小柚瀏覽器本身是約 130 KB 的 C 程式（分頁、網址列、選單、下載…），網頁的排版與
  JavaScript 交給系統的 WebKitGTK。不用自帶一整套瀏覽器引擎，安全性更新也跟著系統一起來。
- **行程少**：一個介面行程、一個網路行程，加上每個網站一個網頁行程；只開一個網頁時總共 3 個行程。
  Chromium 與 Firefox 另外還有 GPU、各種服務與預先開好的備用行程，什麼都還沒開就有 9～11 個。
- **沒有顯示卡就用 CPU 畫**：沒有獨立顯示卡的電腦（包括虛擬機）用軟體模擬 OpenGL 時，每個行程要多佔一百多 MB，
  畫得也不會比較快。小柚瀏覽器偵測到沒有 Intel、AMD、NVIDIA 的顯示卡驅動程式時，介面與網頁都直接用 CPU 繪圖。
- **不留著舊網頁**：換到別的網站時不保留上一個網頁的行程（「上一頁」改成從快取重新顯示），不會越開越多。
- **主動釋放快取**：網頁行程用超過約 340 MB 時開始釋放圖片、JavaScript 編譯結果等快取，超過 512 MB 時釋放得更積極。

## 代價與限制

- **網站相容性**大致等於 Safari：絕大多數網站正常，少數只為 Chrome 設計的網站可能顯示不完整，這時可以改用 Firefox 或 Chromium。
- **沒有**擴充功能、書籤同步，也**不能播放需要 DRM 的串流影片**（例如 Netflix）。
- 這次的數字是**沒有顯示卡**的情況。有顯示卡的電腦上三個瀏覽器都會改用 GPU 加速，記憶體與速度都會不同，這份文件沒有量。
- 記憶體會隨網頁內容改變（廣告、影片、網頁本身的程式）。這裡的三種情況只是代表性的例子，不同網站的差距會不一樣。
