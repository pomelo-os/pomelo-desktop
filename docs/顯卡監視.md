# 顯卡監視（pomelo-gpu）

一個圖形介面加命令列的**唯讀**工具：看有幾張顯卡、各自的型號與規格、使用率、顯示記憶體用了多少、溫度、功耗、時脈、哪些處理程序在用、裝了哪些 AI 模型、哪些模型現在載入在顯示記憶體裡。

NVIDIA 專有驅動不是自由軟體：**Pomelo 不隨附、不打包、不下載、不在安裝流程自動安裝**。驅動由使用者自己裝（驅動會附帶 `nvidia-smi`），裝好以後 pomelo-gpu 就讀取並顯示。沒有驅動時只做偵測與說明。

啟動器的「工具」裡有「顯卡監視」，也可以在活動監視器的「顯卡」分頁按「開啟顯卡監視」。

## 一眼看懂

- **總覽**：頂端橫幅用一句話說結論（綠「N 張顯卡運作正常」、橘「有注意事項：…」、紅「有問題：…」），右邊是彙總（總顯示記憶體、總功耗、載入的模型數）。每張顯卡一張卡片：型號、驅動版本、顯示記憶體圓環（超過 90% 轉橘、97% 轉紅）、GPU 使用率、溫度、功耗（W／上限）、時脈（對最大值）、風扇、PCIe 世代與寬度、效能狀態（P0…）、降頻原因。點卡片進入詳情。建議（為什麼重要、建議做法、按鈕）放在卡片下方。
- **詳情**：全部欄位（UUID、PCI 位址、VBIOS、運算能力、ECC、MIG 實例、編碼器／解碼器使用率、PCIe 吞吐量 TX／RX…）、即時折線圖（最近 60 秒與最近 10 分鐘兩種視圖，可選指標、顯示平均與最大、游標移上去顯示數值、暫停／繼續、匯出 CSV 與 PNG）、使用這張卡的處理程序。
- **處理程序**：PID、名稱、使用者、類型（運算／圖形）、顯示記憶體與佔該卡的百分比、指令行（點一下展開；`--token`、`--password`、金鑰與網址中的密碼一律遮成 `***`）、所屬容器（docker／podman／k3s／containerd／cri-o，能查到名稱就顯示名稱，否則顯示容器 ID 前 12 碼）、所屬 systemd 服務。右鍵：複製 PID、複製指令行、結束（SIGTERM，要確認）、強制結束（SIGKILL，要再確認）、在活動監視器查看、查看所屬容器、只顯示這個處理程序。看不到別人的處理程序時說明原因，並可用「以管理員權限檢視」（經 pkexec 執行唯讀的 `pomelo-gpu-admin`，只輸出 GPU 編號、PID、名稱、顯示記憶體）。
- **AI 模型**：上方「目前載入：N 個模型，共佔 X GiB 顯示記憶體」，每個模型一張卡（名稱、服務來源、可信度、佔用、所在顯卡、到期倒數、context 長度）；下方「已安裝（未載入）」清單（Ollama、Hugging Face 快取、.gguf 資料夾、LM Studio），顯示格式、量化、參數量、大小、最後修改時間，並**粗估**放不放得進目前的顯示記憶體（模型大小加約 10% 與 512 MiB 的 KV cache 餘量）。
- **驅動說明**：偵測到 NVIDIA 顯卡但沒有驅動、或 `nvidia-smi` 無法通訊時，說明現況與可能原因，並列出各發行版的官方安裝方式（只是可複製的指令文字，不會執行）與檢查指令（`dkms status`、`mokutil --sb-state`、`dmesg | grep -i nvidia`）。
- **設定**：取樣間隔（0.5／1／2／5 秒）、資料來源（自動／只用 NVML／只用 nvidia-smi）、警示門檻與每項警示的開關、桌面通知、模型相關選項。

## 資料來源

| | NVML 路徑 | nvidia-smi 路徑 |
|---|---|---|
| 怎麼取得 | 執行時 `dlopen("libnvidia-ml.so.1")`，直接呼叫函式（輕量，不開子行程） | 單一長駐子行程 `nvidia-smi --query-gpu=… --format=csv,noheader,nounits -lms N`（視窗可見才跑，隱藏就結束它）；處理程序用 `nvidia-smi -q -x`（XML） |
| 型號、UUID、PCI、驅動、VBIOS、運算能力 | ✔ | ✔ |
| 顯示記憶體（已用／可用／總量，64 位元） | ✔ | ✔ |
| GPU／記憶體控制器使用率、溫度、風扇、功耗與上限、時脈與最大時脈、效能狀態 | ✔ | ✔ |
| PCIe 目前與最大的世代／寬度 | ✔ | ✔ |
| 降頻原因 | ✔ | ✔（`clocks_throttle_reasons.active`，新驅動自動換成 `clocks_event_reasons.active`） |
| ECC 狀態與無法修正的錯誤 | ✔ | ✔ |
| MIG 模式 | ✔ | ✔ |
| MIG 實例清單（名稱、記憶體） | ✔ | ✘（只有模式） |
| 編碼器／解碼器使用率 | ✔ | ✘ |
| PCIe 吞吐量 TX／RX | ✔ | ✘ |
| 處理程序（運算與圖形） | ✔（compute＋graphics，含 `usedGpuMemory`） | ✔（`-q -x`：C／G／C+G；失敗時退回 `--query-compute-apps`） |
| CUDA 版本 | ✔（驅動支援的版本） | ✔（`-q -x` 的 `cuda_version`） |

- **偵測順序**：設定「自動」時先試 NVML，失敗或不存在才用 nvidia-smi（PATH、`/usr/bin`、`/usr/local/nvidia/bin`、`/opt/nvidia/bin`、`/usr/lib/wsl/lib` 找得到就算「NVIDIA 工具已安裝」）。介面與 `--summary` 都顯示資料來源（「NVML」或「nvidia-smi 535.54.03（/usr/bin/nvidia-smi）」）。設定可強制「只用 NVML」或「只用 nvidia-smi」。
- **欄位逐一降級**：不同驅動版本的欄位不同。nvidia-smi 路徑先查全部欄位，被回報「not a valid field」時，先讀一次 `--help-query-gpu` 濾掉不支援的欄位，仍不行就一欄一欄拿掉重試；`[N/A]`、`[Not Supported]`、`[Insufficient Permissions]`、`[Unknown Error]` 一律當成「沒有」，欄位數對不上的整行不採用（免得錯位）。NVML 路徑每個函式獨立判斷回傳碼（例如 GeForce 沒有 ECC、舊卡沒有風扇資料）。
- **AMD**：讀 `/sys/class/drm/card*/device/`（`gpu_busy_percent`、`mem_info_vram_*`、`mem_info_gtt_*`、hwmon 的溫度／風扇／功耗／上限、`pp_dpm_sclk`／`pp_dpm_mclk`、PCIe 連結、`product_name`，名稱找不到時查 pci.ids／hwdata）。處理程序由 `/proc/<pid>/fdinfo` 的 `drm-*` 欄位彙總（只看得到自己的處理程序，除非用管理員權限）。
- **Intel**（i915／xe）：名稱、`gt_cur_freq_mhz`／`gt_max_freq_mhz`、hwmon；使用率由 fdinfo 的 `drm-engine-*` 彙總，沒有就用 RC6 的「活動度」粗估；整合式顯卡的顯示記憶體與系統共用。
- **虛擬顯示卡**（virtio、QXL、VMware、Hyper-V、Bochs、VirtualBox…）：只列名稱、驅動、PCI 位址與連接的螢幕，明說沒有用量資料。
- 所有顯示卡都列出，標示類型（獨立／內建／虛擬）、驅動（nvidia／nouveau／amdgpu／i915／xe／virtio…）、PCI 位址、連接的螢幕（由 `/sys/class/drm/card*-*/status` 與 EDID 名稱）。

## AI 模型的偵測方式

只查本機（`127.0.0.1` 與 UNIX socket，逾時 1 秒，失敗就略過）；**不掃描網路**。

| 方法 | 可信度 | 說明 |
|---|---|---|
| Ollama `GET /api/ps`、`/api/tags`；Ollama 服務狀態（systemd） | 服務回報 | 名稱、大小、`size_vram`、到期時間、context；已安裝清單另外直接讀 `~/.ollama/models/manifests`，不需要服務在跑 |
| Pomelo 小幫手的 llama-server（UNIX socket） | 服務回報 | `/props`、`/v1/models` |
| 一般 llama-server（TCP） | 服務回報；服務沒回應時「指令行判斷」 | 從處理程序指令行解析 `-m`／`--model`、`--port`、`-ngl`、`-c`，再查 `/props` |
| vLLM、LM Studio、其他 OpenAI 相容服務 | 服務回報 | 由處理程序反推埠；只有使用者在設定勾選「掃描本機常見的 AI 服務埠」才查 8000、8080、1234、5000、7860 |
| 由使用 GPU 的處理程序反推 | 推斷 | 打開（fd）或映射（maps）的 .gguf／.safetensors／.onnx／.pt… 檔案，或由名稱與指令行認得 PyTorch、TensorFlow、vLLM、llama.cpp、ComfyUI、Stable Diffusion WebUI、text-generation-webui、Triton 等 |

每個模型標示佔用的顯示記憶體（Ollama 的 `size_vram` 或處理程序的用量）與所在顯卡（多卡時由處理程序所在卡判斷，判斷不出來標示「未知」）。只讀檔名與大小，不讀模型內容。

控制預設全部只讀。**不提供載入、刪除模型**；只有 Ollama 在使用者於設定勾選「允許管理 Ollama 模型」後，才出現「卸載」按鈕（`keep_alive=0`，要確認）。

## 警示

資料驅動的規則表（`alerts.c`）：溫度 ≥ 85 °C 橘、≥ 90 °C 紅；顯示記憶體 ≥ 90% 橘、≥ 97% 紅；因過熱或功耗上限降頻；風扇 0 RPM 且溫度高；ECC 錯誤；PCIe 寬度降低；有 NVIDIA 顯卡但沒載入驅動；使用 nouveau；nvidia-smi 無法與驅動通訊；顯卡失去連線。門檻與每項開關都在設定。每項警示有「為什麼重要」與「建議做法」。

通知（選用）：設定打開後，視窗開著時發現新警示會用 `notify-send` 通知，同一警示 30 分鐘內一次。要在視窗關著時也檢查，可以啟用（預設關閉）：

```
systemctl --user enable --now pomelo-gpu-check.timer      # 每 5 分鐘 pomelo-gpu --notify-check
```

## 命令列

```
pomelo-gpu [--summary] [--json] [--list] [--gpu N] [--processes] [--models]
           [--watch [秒]] [--csv 檔案 --duration 秒] [--brief] [--notify-check]
           [--page overview|detail|processes|models|guide|settings] [--help]
```

結束碼：0 正常、1 有警示、2 有問題、3 沒有顯卡。`--json` 是結構化輸出（`version`、`source`、`status`、`gpus[]`、`processes[]`、`alerts[]`、`models.loaded[]`／`installed[]`；未知的值是 `null`）。`--brief` 是給主機醫生用的一行。

## 效能與隱私

- 開啟時先畫外框，取樣與模型偵測都在背景執行緒；視窗隱藏或最小化（X11）就停止取樣，並結束長駐的 nvidia-smi。取樣間隔預設 1 秒（0.5～5 秒）。處理程序（要掃 /proc）每 3 秒以上才更新一次。
- 所有資料只在本機，不上傳；指令行中的敏感參數遮蔽。

## 限制

- 沒有在真實 NVIDIA 硬體上測過：NVML 與 nvidia-smi 路徑都是用假的函式庫與假的 nvidia-smi 腳本驗證（照官方輸出格式）。
- 原生 Wayland 視窗沒有「是否可見」的資訊，視為一直可見（取樣不會因最小化而停止）。
- 折線圖游標提示靠詢問游標位置，只有 X11 視窗；原生 Wayland 只在點擊或重畫時更新。
- AMD 與 Intel 沒有 NVML 那樣的完整資料；Intel 的使用率是由 fdinfo／RC6 推得。
- 顯示記憶體的「放不放得下」只是粗估。
- 唯讀：不調整風扇、功耗上限、時脈。
