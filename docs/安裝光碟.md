# Pomelo 安裝光碟（Ubuntu 26.04 改裝版）

這是一份「先試用、再決定要不要裝」的安裝光碟，概念跟官方 Ubuntu Desktop 的 Live CD 一樣：開機後直接進到可以用的 Pomelo 桌面，覺得可以再安裝到硬碟。跟一般安裝 Pomelo（裝在既有的 Ubuntu/Fedora/Rocky 上）不同，這份光碟整台機器從開機就是 Pomelo，不需要先裝好 Linux 再裝 Pomelo 套件。

目前只有 **Ubuntu 26.04 LTS** 這一版，是改裝自官方 `ubuntu-26.04.1-desktop-amd64.iso`：移除了 GNOME 桌面、LibreOffice、ibus 輸入法（Pomelo 都有自己的等價物），換成 Pomelo 桌面（pomelo-compositor + pomelo-dm），其他部分（開機程式、安裝程式、硬體支援）維持官方原樣。

## 下載與寫入隨身碟

ISO 檔案：`pomelo-ubuntu-26.04.1-desktop-amd64.iso`（約 5.9 GB，比官方原版 6.48 GB 小）。

寫入隨身碟（會清空整支隨身碟，注意代號不要選錯）：

```sh
# 先用 lsblk 確認隨身碟是哪一個代號（例如 /dev/sdb），不要選到自己的硬碟
sudo dd if=pomelo-ubuntu-26.04.1-desktop-amd64.iso of=/dev/sdX bs=4M status=progress conv=fsync
```

Windows／macOS 可以用 [balenaEtcher](https://etcher.balena.io/) 或 Rufus，跟寫官方 Ubuntu ISO 的流程一樣。

## 開機

電腦開機時按對應廠牌的鍵（常見是 F12、F2、Esc、Del）叫出開機裝置選單，選剛剛寫好的隨身碟。BIOS 跟 UEFI 開機都支援（沿用官方 ISO 的開機結構，沒有改過）。

開機選單選「Try or Install Ubuntu」（目前還是沿用官方 GRUB 選單文字，還沒改成 Pomelo 字樣）。

![開機畫面：UEFI 韌體（TianoCore）交給 GRUB，跑出 Ubuntu 開機動畫](圖/安裝光碟/01-開機畫面.png)

## 開機後：直接是 Pomelo 桌面

跟官方 Live CD 不一樣的地方：官方版開機後是 GNOME 桌面，這份改裝版開機後**自動登入直接進 Pomelo 桌面**（使用者是 `ubuntu`，不用輸入密碼）——這是 live 環境本來就有的「ubuntu 自動登入」機制，Pomelo 這邊只是把它要登入的桌面換成 pomelo-dm／pomelo-compositor，不是另外加的功能。

這個階段的桌面是跑在記憶體裡的，試用時做的任何修改（裝軟體、改設定、建檔案）重開機都會消失，想保留東西要先安裝到硬碟。

![開機後自動登入，進到 Pomelo 的選單列與 Dock](圖/安裝光碟/02-開機後的桌面.png)

> 這張截圖是在 QEMU 虛擬顯示卡下拍的，Dock 疊了一條多餘的視窗邊框、圖示變成色塊——這就是下面「已知問題」提到的外觀小瑕疵，不是正常樣子（正常應該跟[使用手冊](使用手冊.md.in)裡的桌面截圖一樣乾淨），先如實附上。

## 安裝到硬碟

安裝程式沿用官方 Ubuntu 的圖形安裝精靈（`ubuntu-desktop-bootstrap`，Canonical 官方近年改用 Flutter 寫的那一套，裝在 snap 裡），這份光碟沒有動它，流程應該跟平常灌 Ubuntu 一樣：選語言／鍵盤、選磁碟分割方式、建立使用者帳號、跑完重開機。

> **目前狀態**：改裝光碟的開機、自動登入、Pomelo 桌面本身都已經實際開機測試過，確認正常；但圖形安裝精靈從「開始安裝」到「跑完重開機」這整段點擊流程，這次還沒有機會完整跑過一遍驗證（QEMU 測試環境的滑鼠點擊一直對不準，卡在這一步），用之前請自己先跑一次確認。安裝精靈本身的 snap 套件跟它需要的執行環境都還在，沒有被移除套件的那一輪動到。

## 安裝完成後

因為 Pomelo 桌面已經是這份光碟 squashfs 內容的一部分，裝到硬碟後的系統**開機就直接是 pomelo-dm 的登入畫面**，不需要再額外執行 `sudo pomelo-dm-switch on`（一般「在既有系統上裝 Pomelo」才需要這個步驟，這份光碟已經先切好了）。

其他跟一般 Pomelo 桌面一樣：系統設定在「控制中心」，輸入法、外觀、使用者等設定方式見 [docs/使用手冊.md.in](使用手冊.md.in)。

## 已知問題

- **Dock 外觀偶爾跑位**：在 QEMU 的虛擬顯示卡（bochs-drm）環境下，Dock 偶爾會疊出一條多餘的視窗邊框跟紅黃綠按鈕，位置也沒有正確貼齊螢幕上緣，圖示會變成色塊而不是正常圖案。真實硬體上是否會重現還沒驗證，先記錄下來。
- **圖形安裝精靈的完整點擊流程未驗證**，見上一節。

## 給之後維護用：怎麼重新產生這份光碟

這份光碟是用底下流程做出來的，之後 Ubuntu 26.04 出新的 point release，或 Pomelo 版本更新了，照這個流程重做一份：

1. 下載官方 ISO：`https://releases.ubuntu.com/26.04.1/ubuntu-26.04.1-desktop-amd64.iso`（下載後用官方 `SHA256SUMS` 核對）。
2. 把 ISO 裡 `casper/minimal.squashfs`、`casper/minimal.standard.squashfs`、`casper/minimal.standard.live.squashfs` 三層用 overlayfs 疊合掛載成一個完整檔案系統（minimal 是基底、standard 是加值到「完整版」的差異層、live 是 live 階段才需要的額外差異層）。
3. chroot 進去，裝這次打包好的 Pomelo 42 個套件（`dist/ubuntu26.04/*.deb`），`apt purge` 掉 `ubuntu-desktop-minimal`／`gnome-shell`／`gdm3`／`libreoffice*`／`ibus*`，再 `apt autoremove --purge` 清沒人要的相依。
4. 用 `POMELO_DM_SWITCH_ROOT=<merged 目錄> pomelo-dm-switch on` 把預設登入管理員切成 pomelo-dm（這個腳本本來就支援指定別的根目錄，不用另外寫）。
5. 修改 `/usr/share/initramfs-tools/scripts/casper-bottom/15autologin`，比照既有的 GDM／LightDM／SDDM 寫法，新增一段讀寫 `/etc/pomelo/dm.conf` 的 `autologin-user=`，再用 `update-initramfs -u` 重新產生 initrd（casper 原本不認得 pomelo-dm，不補這段開機不會自動登入）。
6. 清乾淨（apt clean、清 log、清 machine-id），整個目錄 `mksquashfs` 成一份新的 `minimal.squashfs`（取代原本三層），`minimal.standard.squashfs`／`minimal.standard.live.squashfs` 換成空的占位 squashfs（內容已經全部併進新的 minimal.squashfs，但 casper 開機時的分層邏輯要看到這兩個檔案存在才不會報錯）。
7. 更新 `casper/install-sources.yaml`、`casper/*.size`、`md5sum.txt` 裡對應檔案的雜湊值。
8. 用 `xorriso -indev 官方ISO -outdev 新ISO -rm <要刪除的多語系/secureboot squashfs> -- ... -map <改好的檔案目錄> / -boot_image any replay -volid "Pomelo 26.04"` 封裝——`-boot_image any replay` 會照抄官方 ISO 原本的開機結構（BIOS＋UEFI 雙開機），不用自己重建 GRUB／El Torito。
9. **重要**：initrd 重建後 `/conf/uuid.conf` 會換成新的隨機 UUID，但 casper 開機時會拿它去比對 ISO 上 `.disk/casper-uuid-generic` 的內容，兩邊對不起來會直接判定「找不到合法的 live 媒體」開不了機——封裝前要把這個新 UUID 寫回 `.disk/casper-uuid-generic`（連同它的 md5sum 一起更新）。
10. 用 QEMU＋OVMF（UEFI）開機驗證：`qemu-system-x86_64 -enable-kvm -m 4096 -cdrom 新ISO.iso -drive if=pflash,...OVMF_CODE... -drive if=pflash,...OVMF_VARS... -serial file:serial.log`，序列埠的 log 比對著畫面截圖（`-monitor unix:...` 用 `screendump` 指令）看好用很多，初期除錯直接看 serial.log 就好。

另外這次順便修掉一個會影響所有已打包套件（不只這份光碟）的 bug：`pomelo-compositor` 啟動的 XWayland 預設是開著存取控制的，`pomelo-greeter` 用沒有權限的帳號執行、UID 跟 compositor（root）不同，連線一律被拒絕。修法是 `pomelo-compositor/ipc.c` 的 `SETUID` 處理多做一步，用 X11 的 `ChangeHosts` 協定請求把對應帳號加進 Xwayland 的 `SI:localuser:` 信任名單（效果等同 `xhost +SI:localuser:<帳號>`），不需要額外管理一份 Xauthority cookie 檔。這個修正已經包含在這次所有五個發行版的 0.35 套件裡。
